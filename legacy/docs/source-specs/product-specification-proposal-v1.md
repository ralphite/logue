# 跨网页输入与项目记忆产品 — Product Proposal v1.0

> 这是基于现有需求做出的产品设计提案，不替代忠实记录需求的 v0.3。本版包含必要的产品判断，目标是形成一个真正好用、能产生长期复利、同时不过度设计的产品。

## 1. 一句话定义

一个本机运行、以浏览器 Extension 为入口的**项目感知输入工具**：用户在主流网页输入框中通过语音、文字或摘录快速表达和采集；内容在完成眼前任务的同时沉淀为可追溯的项目记忆，并被后续输入、Agent 和 View 有控制地复用。

产品承诺可以概括为：

> **表达一次，立刻使用；保存下来，以后不必重复交代。**

## 2. 核心产品判断

现有设想中的功能方向基本正确，但缺少主次。最好的产品不应把语音输入、知识库、项目管理、View 和 Agent 平台同时作为中心，而应形成三层关系：

1. **输入是入口和即时价值**：说完或选中内容后，几秒内完成当前网页中的工作。
2. **项目记忆是长期价值**：用户最终采用的表达、网页资料和 Agent 结果逐渐让系统更懂项目。
3. **View 与外部 Agent 是复用方式**：它们消费已有项目记忆，不另建一套内容世界。

因此，**项目感知输入是 V1 的产品楔子，不是长期边界**。产品首先成为一个每天自然使用的输入层，再逐渐成为用户和 Agent 共用的本机项目记忆底座。用户不需要为了“维护知识库”而使用它。

## 3. 核心用户与问题

首要用户是同时处理多个项目、经常在网页、邮件、聊天和 Coding Agent 中表达复杂内容的知识工作者。他们反复遇到三个问题：

- 语音输入不理解项目术语、专有名词和已有决定，仍需大量修改；
- 同一背景、要求和个人偏好需要向不同的人与 Agent 反复说明；
- 说过的话、网页资料和分析结果散落在不同产品中，之后无法可靠复用。

核心任务不是“整理所有个人知识”，而是：

> **不中断当前工作，把想法准确地放进正在使用的网页，并让这次表达帮助下一次表达。**

## 4. 用户心智模型

用户只需要理解三个主要对象：

| 对象 | 用户理解 | 关键边界 |
|---|---|---|
| **资料** | 一次主动输入、采集、导入或 Agent 返回的内容 | 保存事实与来源；可属于零个或多个项目 |
| **项目** | 一项持续工作的范围和默认记忆 | 不是普通标签；包含相关资料、项目概览、术语和 View |
| **View** | 使用项目内容形成的成果或交互方式 | 是派生结果，不替代原始资料；V1 先支持可编辑文档 |

普通 Tag 只是资料的轻量属性，不形成层级。`Context` 不是页面或对象，而是一次操作时系统实际选取的资料集合。Glossary 也不是一级模块，而是个人或项目中的辅助能力。Agent 是处理者，不是主导航。

“项目知识”在 UI 中不另建一座知识库，而表现为项目中的一份**项目概览**：它记录当前背景、决定和重要术语，由用户直接编辑；用户显式请求时，Agent 可以基于资料生成带来源的更新草稿。

## 5. 核心价值闭环

`表达或采集 → 立即完成当前任务 → 保存原始资料与插入版本 → 关联项目 → 改善项目记忆 → 改善下一次输入或 View`

这个闭环有两条硬要求：

- **采集不能依赖整理**：不选项目、不加 Tag，也能立即完成并保存。
- **沉淀必须产生复用**：资料数量不是价值；以后少改一次术语、少重复一段背景或更快生成一个可靠成果才是价值。

## 6. 三条核心 Journey

### 6.1 在任意网页中输入

1. 用户聚焦输入框，通过快捷键或 Extension 开始录音，也可直接输入文字。
2. 浮层只展示录音状态和“本次参考”的一个项目；系统可以建议，无法可靠判断时默认不使用项目，不强迫用户选择。
3. 浮层用一行非阻塞摘要说明将发送给 Gemini 的范围，例如“语音、页面标题、项目 A”；首次使用或发送范围扩大时才要求确认。
4. Gemini 使用最小必要页面信息、一个参考项目的概览与已确认术语、用户明确保存的个人说明，以及近期用户最终采用的表达生成文字。
5. 结果进入可快速修改的预览；主动作是“使用并保存”：保存成功后写入输入框，但绝不自动提交网页表单，也不再要求第二次确认。
6. 系统保留原始音频、模型结果、预览中修改后的插入版本、页面来源和本次实际引用的已有资料。取消预览则不保存，临时音频和页面信息不进入资料流。
7. V1 的语音理解只使用一个参考项目；保存后的资料仍可关联零个、一个或多个项目。额外归属可在轻提示或资料流中补充，不影响当次生成。

V1 只保存 Extension 内主动输入的文字，或用户明确执行“保存此段”的网页文字；普通键盘输入和写入网页后的继续编辑永不被动记录。

### 6.2 快速采集网页资料

1. 用户选中页面内容，通过右键菜单选择“保存到应用”。
2. 内容立即保存，不弹出完整表单；轻提示显示来源和建议项目，用户可一键更改或保持未归项目。
3. 系统保存选中文字、URL、页面标题和采集时间。URL 是定位信息，实际选中文字才是被保存的资料。
4. 资料随后可参与项目输入、Agent 分析和 View 生成；系统不会默认保存整张网页。

### 6.3 从项目记忆得到成果

1. 项目页集中显示用户维护的项目概览、关联资料和已有 View。
2. 新资料不会自动产生审核任务。只有用户显式请求时，Agent 才基于选定资料生成一份带来源的概览更新草稿；用户采用后才进入以后默认使用的项目记忆。
3. 用户可从项目创建一个 View。V1 的 View 是带来源引用、可继续编辑的文档；Chatbot、页面和通用 View Builder 后续再做。
4. 外部 Agent 可以读取项目的只读资料包，访问产品本身无法处理的链接或完成多来源分析，再以新的派生资料或 View 追加回来。若分析依赖外部文档，应同时保存取得的原文快照与独立的分析结果，不能只留下 URL 和结论。

## 7. Context 与动态 Glossary

系统不提供 `Context Policy`、规则 DSL 或独立 Context 页面。每次语音处理默认只使用：

- 当前页面的标题、去除不必要敏感参数后的 URL，以及用户明确选中的内容；
- 一个参考项目的用户维护概览与已确认术语；
- 用户在设置中明确保存的个人说明和个人 Glossary；
- 用户已经“使用并保存”的近期内容，以及用户接受的词汇建议。

资料可以属于多个项目，但不能因此自动混合多个项目的 Context。V1 的网页输入始终最多使用一个参考项目；跨项目综合只发生在用户显式发起的 Agent 分析或 View 生成中。

Glossary 只分两类：用户固定的词，以及系统从最终采用内容中得到的建议。用户可以固定、纠正或忽略建议；原始转写、未采用结果和单次 Agent 猜测不能直接成为强记忆。

录音前以一行摘要显示发送范围，结果详情中可展开查看“本次实际参考了什么”；用户不需要手工组装 Context。

## 8. Agent 的产品边界

产品利用外部 Agent 的能力，但不在 V1 中建设 Agent 平台、连接管理器或工作流引擎。Agent 在产品之外运行，本产品只提供窄而稳定的交换边界。

- 外部 Agent 可获得某个项目或用户指定范围的只读资料包。
- 写回只允许通过简单导入或受限的追加接口新增带来源的资料、分析或 View，不直接覆盖原始资料。
- Agent 结果明确标注处理者、输入来源和派生关系。
- Agent 只有在用户显式请求时才生成项目概览更新草稿；影响以后 Context 的内容必须由用户采用。
- 删除、项目合并、批量重分类和改写原始资料不交给 Agent 自动执行。

Agent 写回的结果直接作为带有 `Agent` 来源标识的新资料出现在资料流和相关项目中，不另建 Agent Inbox。未来需要管理 Agent 连接时，再把它放入设置。

## 9. 信息架构

一级导航保持简单：

- **资料流**：所有进入系统的资料，包括用户主动保存、网页采集和 Agent 派生结果。它不是需要清零的 Inbox；“未归项目”只是一个筛选条件。
- **项目**：查看项目概览、资料和 View，也是默认复用边界。
- **View**：集中查找和继续使用各项目产生的成果；同一 View 也出现在所属项目中。
- **设置**：Gemini、Extension、个人说明、个人 Glossary，以及数据导出与恢复。

项目页只需三个主要区域：**概览、资料、View**。来源链、模型信息和操作记录放在资料详情中，不占据主界面。

## 10. 数据与信任

- 产品只在本机运行；Extension 只访问本机 API；Gemini Key 只保存在本机后端。
- 本机保存不等于数据从不离开机器：语音和被选中的 Context 会发送给 Gemini，界面必须清楚显示发送范围。
- 只有用户主动录音、输入、采集、导入、确认保存，或明确授权的外部 Agent 追加的内容才进入产品；不被动记录网页活动或所有键盘输入。
- 已保存内容不自动过期或删除，只有用户明确删除时删除。一次主动输入或采集形成一项资料；原始内容、模型结果和插入版本都不被覆盖。可独立复用的摘要、分析和 View 是新的派生资料。
- 派生内容必须引用生成时实际使用的具体来源版本，不能只模糊地指向一项后来可能被编辑的资料。
- 内容以普通文件承载；结构化索引只负责稳定身份、项目/Tag 关系、来源链和检索。物理 Folder 不表达项目归属，精确数据库技术留给技术设计决定。
- 外部 Agent 读取的是可重新生成的只读项目资料包；写回只追加新内容，不能直接编辑产品的底层资料文件。
- 因为产品承诺长期保存，V1 至少要有经过验证的整库导出与恢复方式，以及单项手动删除；这不是同步系统或复杂备份产品。

## 11. 最小可用版本

V1 必须完整跑通以下能力：

1. Extension 在主流标准输入框和明确支持的富文本编辑器中完成录音/文字输入、Gemini 处理、快速修改、使用并保存；
2. 网页选中文字后一键保存；
3. 资料流、搜索、来源详情、零至多个项目和普通 Tag；
4. 用户可编辑的项目概览、项目资料和单一参考项目 Context；
5. 固定 Glossary，以及从用户确认使用的插入版本产生的少量词汇建议；
6. 原始音频、机器结果、插入版本和派生来源的完整保存；
7. 一个带来源的可编辑文档 View；
8. 项目只读资料包，以及外部 Agent 结果的简单导入或追加式写回；
9. 单项删除，以及可验证的整库导出与恢复。

明确不做：跨机器或云同步、被动全量记录、传统文件管理器、Folder 层级、知识图谱、自动项目合并、历史自动重分类、多项目 Context 自动混合、复杂 Agent 编排、任意 View Builder、Chatbot Runtime、站点发布和 Context Policy。

## 12. 验证产品价值

第一阶段不以“保存了多少资料”为成功标准，而观察四件事：

- **即时有效**：语音结果被插入和采用的比例、修改量、停止录音到可用文字的等待时间；
- **持续变好**：同一项目使用一段时间后，术语错误与背景补充是否明显减少；
- **复用发生**：已有资料是否实际参与后续输入、Agent 分析或 View，而不是只被存档；
- **负担足够低**：大多数采集无需打开主应用，也无需当场整理或确认多个选项。

北极星不是资料总量，而是：**每周成功完成的、复用了既有项目记忆的输入与成果数量。**

## 13. 必须守住的风险边界

1. **延迟或过度改写**会直接破坏入口价值：预览必须可快速修改，且永不自动提交。
2. **多项目污染**会让 Context 失去可信度：归属可以多选，默认理解项目只能有一个。
3. **错误自我强化**会让产品越用越差：只有用户最终采用、反复出现或明确固定的内容可形成强信号。
4. **Agent 结果冒充事实**会破坏项目记忆：Agent 输出先作为带来源的派生资料，不能静默进入已确认概览。
5. **资料流变成整理负债**会降低使用率：未归项目不是错误，系统不能用红点或待办压力要求清空。
6. **“本机”造成虚假安全感**会伤害信任：必须明确哪些音频和页面内容会被发送给 Gemini。

## 14. 本提案做出的三个关键选择

1. **以项目感知的跨网页输入为产品楔子**，而不是以通用知识管理为入口。
2. **允许 Agent 追加带来源的派生内容，但项目概览更新必须由用户显式发起并采用；Agent 不得静默改写原始资料或已确认项目记忆。**
3. **V1 只实现一种 View：带来源的可编辑文档**；Chatbot、页面和通用生成能力等核心闭环成立后再扩展。

这三个选择决定了产品是否足够聚焦，也最值得在进入 UI 设计前由用户确认。
