# macOS ChatGPT 应用 · Codex 界面功能规格

本文档用于**像素级复刻** macOS 版 ChatGPT 桌面应用中的 **Codex** 工作区界面。
所有数值均为**逻辑坐标 / 逻辑像素（pt）**；截图为 Retina @2x，图像像素 = 逻辑值 × 2。

> **隐私说明**：本文档只描述界面的**结构、几何与样式**。截图中出现的真实项目名、任务标题、
> 分支名、文件路径、终端输出一律替换为通用占位（「项目 A」「任务标题 1」`feature/xxx`
> `src/moduleA/FileA.ext` 等）。请不要按占位文字去推断真实内容。

### 0.2 标注约定

每条信息都带证据等级：

- **[已验证]** —— 可从上述三张截图**逐像素扫描**直接读出（几何、配色、字带高度、
  字符步进均为实测），或来自 Accessibility API 导出的**菜单树**（权威、完整），
  或来自下面记录的**两次实际按键操作**。
- **[未验证／推测]** —— 未经实际操作确认。**绝大多数控件的行为属于此类**：
  只实际触发过 `⌘⇧E` 与 `` ⌃` `` 两个菜单项，其余按钮、菜单项、悬停态、选中态、
  动画、右键菜单、空状态、错误态全部**没有点过**。

> 一句话概括：**静态外观是逐像素实测的；两条面板开关路径是实测的；其余交互全是推测的。**

### 0.3 关键限制：Electron 应用不暴露内部 accessibility 树

**[已验证]** ChatGPT 是 Electron 应用，其渲染进程**没有把内部控件暴露到 macOS 的
accessibility 树**。`axdump.js elements` 对该窗口只返回 **12 个元素、其中 3 个可点击**，
而这 3 个全部是窗口自身的**关闭 / 最小化 / 全屏**按钮。

由此产生三条必须记住的限制：

1. **窗口内控件无法枚举**。侧栏条目、标签页、按钮、文件树节点、终端标签，
   在 AX 层面**完全不可见**。
2. **覆盖率的分母未知**。无法回答「这个界面一共有多少个控件、我们覆盖了百分之几」，
   因为没有任何权威清单可以做分母。本文档只能说「截图里能看见的元素都写了」。
3. **无法用 AX 交叉验证**。与 `demos/calc`（Calculator 是原生 AppKit 应用，
   每个按键都能从 AX 树读到 role/title/frame）不同，这里所有界面元素**只能从截图读**，
   没有第二个信息源可以互相印证。文字识别、图标语义、控件边界都存在读错的可能。

**唯一可靠的结构性信息来自菜单栏**——菜单栏属于应用主进程，AX 可以完整读出。
因此本文档以 **View 菜单暴露出来的能力**为骨架来组织（见 [1.1](#11-codex-是一个完整的开发环境)）。

### 0.4 已实测的两次交互

| # | 操作 | 结果 | 像素差异 | 变化区域包围盒（逻辑坐标） |
|---|---|---|---|---|
| 1 | 基态 → 按 `⌘⇧E`（Toggle File Tree） | 右侧面板新增并激活「Open file」标签页，最右切出文件树列 | 2.96% | (757.5, 16.5) – (1367, 854) |
| 2 | 上一状态 → 按 `` ⌃` ``（Open Terminal） | 底部切出终端面板，中间列与右侧面板同时被压缩 | 2.90% | (255.5, 17.5) – (1349, 838.5) |

从这两次差异得出的**结构性结论 [已验证]**：

1. `⌘⇧E` 的影响**严格限制在 x ≥ 757.5 的右侧面板内**——左侧栏与中间对话列
   **一个像素都没有变**。说明文件树是**右侧面板的一个标签页内容**，而不是独立的第四栏。
2. `` ⌃` `` 的终端面板是**挤压式（push）而非覆盖式（overlay）**：中间列的输入框
   从 `y 739.5–838.5` 上移到 `y 459.5–558`（高度不变，仍是 99），右侧面板内容
   同步截断到 `y 574`。
3. 终端面板**不覆盖左侧栏**（x < 240 区域零差异），只横跨中间列 + 右侧面板。

## 1. 总体架构

### 1.1 Codex 是一个完整的开发环境

**[已验证]**（来自 AX 菜单树）View 菜单暴露的能力表明，Codex 不是「一个带侧栏的聊天窗口」，
而是一个**具备 IDE 骨架的开发环境**：

| 能力 | 菜单项 | 快捷键 | 本文档章节 |
|---|---|---|---|
| 侧栏 | Toggle Sidebar | `⌘B` | [3](#3-左侧导航栏sidebar) |
| 底部面板 | Toggle Bottom Panel | `⌘J` | [6](#6-底部终端面板) |
| 终端 | Open Terminal | `` ⌃` `` | [6](#6-底部终端面板) |
| 文件树 | Toggle File Tree | `⌘⇧E` | [5.6](#56-open-file-标签页查看器--文件树) |
| 代码审阅面板 | Toggle Review Panel | `⌘⌥B` | [5.3](#53-review-标签页diff-工具条)–[5.5](#55-review-标签页diff-行渲染) |
| **内置浏览器** | Open Browser Tab / Focus Browser Address Bar / Reload Browser Page | `⌘T` / — / `⌘R` | **未捕获截图** |
| 打开工作区 | Open Folder… | `⌘O` | — |
| 固定摘要 | Toggle Pinned Summary | — | **未捕获截图** |

**[未验证／推测]** 「内置浏览器」与「Pinned Summary」没有截图证据，只能从菜单项名称推断：
- `Open Browser Tab ⌘T` 很可能在右侧面板里再开一个标签页（与 Review / Open file 并列），
  内嵌一个带地址栏的 WebView，用于预览本地开发服务器。这与 `Focus Browser Address Bar`
  和 `Reload Browser Page ⌘R` 两项互相印证。
- `Reload Browser Page ⌘R` 在截图对应的时刻是 **disabled**（`"enabled": false`），
  其余 View 菜单项均为 enabled——说明当前没有打开浏览器标签页。这是「浏览器标签页确实是
  一种可开可关的标签页」的间接证据，但**没有实际打开过**。

### 1.2 窗口与分区

**[已验证]** 窗口逻辑尺寸 **1367 × 854**，四角圆角 **≈13**（squircle，与 macOS 系统窗口一致）。
无独立标题栏——窗口控制按钮直接落在左侧栏顶部（unified titlebar）。

基态布局是**三栏**，从左到右：

```
┌─ 窗口 1367×854，圆角 13 ─────────────────────────────────────────────────────┐
│ ● ● ●  ◫  ←  →  │ 任务标题  ⋯            [VS ⌄] ☰ │ [Review ×] [+]   ⤢ ▭ ◨ │
│                 ├─────────────────────────────────┼────────────────────────┤
│  Codex ⌄     🔍 │                                 │ Last Turn ⌄ +N -N  ⋯ ⋯ │
│  ✎ New chat     │                                 ├────────────────────────┤
│ ────────────────│        消息正文（Markdown）        │ ▼ dir/File.ext  +N -N │
│  任务标题 1       │                                 ├────────────────────────┤
│  任务标题 2       │   ┌─ Edited N files 卡片 ─┐      │ ░ 27 unmodified lines │
│  Show more      │   └───────────────────────┘      │  28  context           │
│                 │                        [commit]  │ ▌29  - removed         │
│  📁 项目 A        │   Worked for 40s ›               │ ▌29  + added           │
│    任务标题 …     │                          [push]  │  30  context           │
│    Show more    │                                  │                        │
│  📁 项目 B        │   ┌─ 输入框 ────────────────┐     │                        │
│    任务标题 …     │   │ ›                      │     │                        │
│                 │   │ + ⚠      5.5 Extra High │     │                        │
│ ────────────────│   │           ⌄  🎤  ⬆      │     │                        │
│ (头像) 用户名  ⬇ │   └────────────────────────┘     │                        │
└─────────────────┴──────────────────────────────────┴────────────────────────┘
   ← 239.5 →        ←────── 516.5 ──────→               ←──── 609.5 ────→
```

### 1.6 设计令牌：字体与字号层级

**[已验证]** 字号由实测的**字带高度**（ascender→descender 的像素跨度）与
**等宽字符步进**推算得出，因此是估算值，误差约 ±1pt。界面字体为 macOS 系统字体
（SF Pro 家族），代码字体为等宽（SF Mono 或同类）。

| 层级 | 估算字号 / 字重 | 实测依据 | 用例 |
|---|---|---|---|
| 品牌 | 17 / 600 | 「Codex」字带 12.5（纯大写高度） | 侧栏顶部 |
| 标题 | 15 / 600 | 中间列标题字带 12.5（含降部） | 中间列头部任务标题 |

### 9.4 细节精度提示

19. **[未验证／估算]** [1.6 节](#16-设计令牌字体与字号层级)的**字号是从字带高度与字符步进反推的**，
