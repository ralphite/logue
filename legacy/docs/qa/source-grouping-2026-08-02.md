# 生成与文档来源：精确重复折叠

时间：2026-08-02 12:20（America/Los_Angeles）

这是一条当前 production Web 的真实运行证据，不是完成声明。测试使用同一真实 `.logue-data`，只读取并展开现有资料，没有创建生成结果、加入引用或写入用户数据。

## 一致规则

- 资料流、生成资料选择器、文档生成对话框和文档“加入正文”现在共用 `kind + trim(content)` 的精确分组键。
- 只有同类型、正文完全一致的捕获才折叠；相同页面标题但正文不同的资料保持独立。
- 默认每组只占一行并显示捕获次数；组级选择只选一个代表来源，避免把重复内容多次发送给 Gemini。
- 展开后，每一次捕获仍按独立 material id 显示，可单独选择或加入引用；来源、项目和日期不丢失。
- 文档来源标题相同但正文不同的资料会显示正文摘要，不再出现无法区分的同名行。

## 当前真实数据验证

- 生成选择器搜索 `Logue keeps every source`：原来的 3 条同类型同内容资料只显示 1 组 `3 次`；展开后显示第 1/2/3 次，分别保留项目信息。
- 折叠组级选择后，顶部计数为 `1 条`，组内显示 `3 次 · 已选 1`，证明默认没有重复装配三个来源。
- 文档来源搜索 `Logue Extension QA Fixture`：5 次捕获被正确表示为 `4 组 · 5 次`；其中完全相同的一组显示 `2 次`，另外三条因正文不同保持独立并展示摘要。
- 展开 `2 次` 后可逐条看到完整来源 metadata；本轮没有点击加入正文，真实文档未修改。
