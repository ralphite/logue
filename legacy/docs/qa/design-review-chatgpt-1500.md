# ChatGPT.com 独立 UX 审查 · 2026-08-02 15:00

## 审查证据

- Web App：7 张当前真实运行截图，覆盖文档编辑/列表、资料列表/详情、语音资料、项目列表/详情。
- Extension：6 张最新构建设计态截图，覆盖输入、录音、转写检查、长选区归档、失败重试和目标失效恢复。
- Web 截图是当前真实运行证据；Extension 截图是 Storybook 设计态，不能替代已安装 Chrome 实测。

## Web App 结论

没有从截图确认 P0；最高影响问题均为 P1：

1. 资料、项目、文档使用不同的 List / Preview / Page 关系，像三个产品。
2. 文档页绕过共享应用壳，Logo、一级导航、连接状态与其它页面不一致。
3. 搜索范围不清：文档局部搜索看起来像全局搜索，项目页又完全消失。
4. “成果 / 文档”双重命名造成对象心智不稳定；决定统一用“文档”。
5. 资料快速预览承担过多持续编辑职责，与完整详情边界不清。

当前批次必须先完成：唯一共享一级导航、明确“搜索文档”、稳定按钮几何与选中态、移动端只保留一套主导航、统一“文档”命名。

## Extension 结论

> 后续用户明确纠正优先于本次外部审查：`review-before-insert` 也太复杂，已废弃。最终强制流程是“聚焦输入框 → 麦克风 → 停止并插入 / 取消”；停止后自动转写、保存、插入，不显示转写审阅或归档选项。

最高影响改进：

1. 固定说明“保存到哪里 / 使用到哪里”，强化保存与插入的结果语义。
2. 统一 Header / Body / Footer 状态骨架，保持主动作位置稳定。
3. 选区保存默认保持轻量：完整原文可滚动只读，归档详情默认收起。
4. 项目感知需要可见但克制；不强迫选择项目。
5. “目标输入框失效但资料已保存”应是恢复提示，不应与转写失败使用同等级错误视觉。

## 本轮独立盲审补充

当前真实运行界面另行复现 6 个 P1：文档页切到项目页时一级按钮整体位移；文档行高度不一；局部搜索语义错误；Extension 在 Logue 自身搜索框覆盖并路由后遗留幽灵按钮；移动端重复两套主导航；移动端核心图标触控目标不足。

这些问题优先级高于继续做局部视觉微调。
