# N13 · 面板收成「一个列表 + 一个输入框」

2026-08-13,你的原话在 [cc/tasks.json](../../cc/tasks.json) 的 **N13** 上,一个字没改。
这份是**方案,不是实现**。按你的规矩:你点头之前,一行产品代码都不动。

## 一、我的理解(一句话)

面板只剩两块:**上面是一条列表**,**下面是一个输入框**。
说话和打字都进这一个输入框,**语音只负责把字填进去,不负责发**;发出去的每一条,底下挂 Ask / As Markdown / Into English 这些技能。

## 二、现在长什么样,为什么要砍

今天的面板([sidepanel.tsx](../../extension/src/sidepanel.tsx),1838 行)有 **三个动词按钮**(Record / Keep / Ask)、**两个录音条**(Ask 框里一个、Record 那个 `RecordControl` 一个)、**四段互不相干的列表**(转写、对话、这页存过的、排队中的),还有一个只在录音时才有意义的隐藏状态 `speaking: "chat" | "dictation"` —— 它存在的唯一理由,就是「有两个地方能说话,得记住这次是对谁说的」。

一个输入框之后,这个状态、这两个录音条、这三个按钮里的两个,全部消失。

| 今天 | 之后 |
|---|---|
| Record 按钮(录音 → 直接存成 Source) | 输入框里的麦克风 |
| Ask 按钮(展开第二个输入框) | 没有了,Ask 是每条记录底下的技能 |
| Keep 按钮(存整页 / 存选区) | 见 §六 第 3 问 |
| 两个录音条,行为不同 | 一个录音条 |
| 四段列表 | 一条列表 |

## 三、输入框(composer)

```
┌──────────────────────────────────────────┐
│ ▎> 被选中的那段文字…            ✕        │  ← 选区引用,可删
├──────────────────────────────────────────┤
│ 在这里打字,或者按麦克风说                │
│                                          │
├──────────────────────────────────────────┤
│ [Logue 项目 ▾]  [记进 · 某文档 ▾]   🎤  ⏎ │
└──────────────────────────────────────────┘
```

**默认范围是整页。** 你在页面上选中一段,面板的输入框自动出现这段的 **Markdown 引用**(`> …`),范围就变成这段。取消选中或点 ✕,回到整页。

技术上要新加一条消息通道:content script 监听 `selectionchange`,把选区文字**和 anchor**(已有的 `TextAnchor`)推给面板。今天面板是临时用 `chrome.scripting.executeScript` 去拿的,拿不到 anchor,也就没法在原地找回来。带上 anchor,这条评论以后能被定位回页面上的那一段。

**长选区**:引用块超过一定长度(建议 600 字)在框里折起来,存下去的是全文,不截断。

## 四、语音(照 chatgpt.com,参考 agentrunner)

录音时,输入框整条变成录音条:

```
┌──────────────────────────────────────────┐
│  ✕    ● 0:12   ▁▃▇▅▂▇▃▁▂▅   [ ✓ ]  [ ↑ ] │
└──────────────────────────────────────────┘
```

| 控件 | 做什么 | 键 |
|---|---|---|
| ✕ | 扔掉,什么都不留 | `Esc` |
| ✓ | 转成文字**插进输入框**,不发 | `↵` |
| ↑ | 转成文字插进输入框**并且发出去** | `⌘↵` |

- **插入 ≠ 提交。** 插完可以接着说第二段、第三段,可以打字改,发不发是另一个动作。这正是你要的「允许用语音多次地输入」。
- 插入落在**光标处**,不覆盖已经打的字 —— 这条今天就有(`joinAtCaret`),保留。
- 转写在后台跑,麦克风立刻放开:说完一段马上能说下一段,不用等模型。
- 转写失败不吃录音 —— 录音先落盘再送模型,失败在列表里出一条带 **Try again** 的记录。这是 [behaviors.md](behaviors.md) 里不能碰的一条。

**这里有一条既有行为被你改掉了**,我照改并记档:
今天「⌘⇧K 开面板即录音,`↵` 直接把话发进对话」。之后 `↵` 只是插进输入框,要再按一次 `⌘↵` 或点提交才发。

## 五、列表:一条流,每条带类型

提交产生一条记录,进同一条列表,新的在上。类型靠 24px 徽章 + 一个动词区分 —— 跟 Web 应用 Activities 那边同一套语言(C2),不另发明一套。

| 类型 | 怎么产生 | 底下存成什么 |
|---|---|---|
| **Comment**(打字) | 输入框有字,提交 | `kind: text` |
| **Comment**(口述) | 语音插入后提交 | `kind: voice`,音频可回放 |
| **Quote** | 输入框只有选区引用,提交 | `kind: selection`,带 anchor |
| **Page** | 存整页 | `kind: page` |
| **Answer / Rewrite** | 某条上跑了技能 | `kind: derived`,缩进挂在母记录下 |

带引用提交时,评论的 `parent_ids` 指向那段引用 —— 「对某段话的评论」这个结构库里已经有了,不用新造。

**每条记录底下是技能条**:`Ask` · `As Markdown` · `Into English` · `⋯`。
这正是你说的「submit 的东西下面有一个 ask markdown into English 这种东西」。今天只有口述的转写才有这一条(`DictatedText`),之后打字的、存的选区、存的整页,一视同仁 —— 它们本来就是同一种东西。

技能跑出来的结果**缩进挂在母记录下面**,不是新起一条。今天口述就是这么做的,保留。

排队中/转写中/失败的录音,不再是列表上方一个独立的盒子,而是列表里一条**状态未完成的记录**。

## 六、要你拍板的(三个)

**1)提交(submit)到底是什么动作?** ← 这个决定了其余全部

- **A(我推荐)· 提交 = 存下这条评论。** 问答不是提交的默认结果,而是记录底下 `Ask` 那个技能。
  依据是你自己那句:「每一次 submit 的东西,下面会有一个 ask……」—— 说明 **submit 之后才轮到 ask**,两者不是一回事。
  好处:一个动词,不用在发之前先决定「这是要存还是要问」;所有记录形状一致。
- **B · 提交 = 发给 agent 问。** 那么「只想存一句话不想被回答」就没有入口了,得再加一个按钮 —— 又回到多动词。

**2)「记进某个文档」这个去处还留吗?**
建议留,但收进输入框那一行,不再是单独一条。理由不是设计偏好,是数据:这个工作区上说过的 33 段话里,33 段再没被用过 —— 「先决定去哪儿」是它们唯一有用的时候。

**3)「存整页」还需要一个自己的按钮吗?**
建议:输入框那行放一个书签图标,一下点掉(不需要打字)。
备选:输入框空着直接提交 = 存整页 —— 更少的控件,但是个看不见的规则。
