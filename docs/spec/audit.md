# T1 · 全面走查

你的要求:"do full audit to find all obvious issues like last one",范围随后扩大到
"ui design must be consistent! everywhere! all levels! … on top of this we must do
audit to follow ui design best practices. ALL"。

**这份是清单,不是改动。** 按你定的规矩:先列清单,你说了才动手。

**怎么查的:量的,不是看的。** 一致性的问题本质是"两个地方是不是一样",那是算术。
在真实浏览器里跑真实工作区,每个路由都**选中真实内容之后**再量(空态和有内容量出来
完全是两回事,第一遍我就栽在这上面),外加左边栏。量的东西:栏宽与内边距、字号、字重、
文字颜色、标题结构、每一个可点区域的尺寸。模型这会儿是断的(key 被封),所以生成类
的状态没能走到 —— 那部分标在最后。

## 值得修的(按值不值得排)

### 1. 两个灰色差 3 个点,人眼分不出来 —— 一个是多余的 ✅ 已修(faint 删除,全部 muted)

```
--color-muted: #70726c
--color-faint: #73756f      ← 差 (3,3,3)
```

量到它们**在同一屏上同时出现**:Documents 里 muted×1 / faint×1,Skills 里 muted×5 /
faint×1,Settings 里 muted×28 / faint×4。**两个 token,一个视觉结果。**

这不是配色问题,是**判断被架空了**:每次写代码的人要在两者间选,而选哪个都一样 ——
于是"次要"和"更次要"这个区分在屏幕上根本不存在,只存在于代码里。要么把 faint 拉开到
真的能看出来(那要先想清楚它比 muted 少说什么),要么删掉一个。

**建议:删掉 faint,全部用 muted。** 三层(ink / ink-soft / muted)够用,四层里有一层
是假的。

### 2. 同一个 `h2`,两种长相 ✅ 已修(统一 560)

| 在哪 | 量到的 |
|---|---|
| Settings 的分区标题 | `h2 12px / 字重 560 / #70726c` |
| Project 里的 "11 Sources" | `h2 12px / 字重 **400** / #70726c` |

同一个标签、同一个尺寸、**不同字重**。两个分区标题,一个粗一个不粗,而它们在层级上
是同一级。挑一个用到两处。

### 3. 三处"数字当入口"的点击区域只有 16–21 像素高 ✅ 已修(三处全部)

| 在哪 | 量到的 |
|---|---|
| Skills · `Revision 2` | 54 × **16** |
| Documents · `Version 6` | 49 × **21** |
| Project · Source 的域名链接(`127.0.0.1`、`chatgpt.com`,一屏 6 个) | 56–78 × **17** |

前两个是我这两天亲手做的 —— "把数字变成入口"这个决定是对的,但我给的是一行小字的
高度。**指针目标的下限是 24 像素**,触屏是 44。16 像素高的东西,点三次中两次。

**建议:给这类"文字即控件"一个统一的最小高度**(垂直内边距撑到 24),而不是三处各调
各的 —— 否则下一个人再做一个就又是 16。

**修了(复量确认)**:三处都到 24–25px,手法是"内边距撑大命中区、负外边距还回版面"
—— Source 行高保持 55px 没长。域名链接改在 `SourceLink` 组件本体上,所以每一处
用它的地方(Stream、面板、RunDialog)一次到位。

### 4. 同一种正文,在不同页面是 11px / 12px / 13px ✅ 已修(11px 档整个删除:`--text-meta` 令牌和全部 `text-[11px]` 收敛到 12px;正文 13、说明 12,复量四路由无一处 11)

量到每个路由里**出现次数最多**的字号:

| 路由 | 主导字号 |
|---|---|
| Projects | **11px**(22 处) |
| Stream | **12px**(12 处) |
| Settings | **12px**(78 处) |
| 左边栏 | **13px**(6 处) |

Projects 整页比 Stream 小一号,而两者装的是同一类东西(条目和它们的说明)。
这和 X25 是同一个病的两种表现:**X25 是页面宽度没人选,这条是字号没人选。**

**建议:定死"正文 = 一个值、说明 = 一个值",别处不许出现第三、第四个。**

### 5. `h1` 把两句话粘成一句,读屏软件念出来是错的 ✅ 已修(h1 = 打开的条目本身;分区名是普通返回按钮,不再在标题里)

量到的可访问名称:

```
"ProjectsAgent Harness"        ← 应该是 Projects › Agent Harness
"DocumentsMy own name for…"
"SkillsAccurate transcrip…"
```

分区名和当前条目在同一个 `h1` 里,中间没有任何分隔。视觉上有 gap 所以看着没事,
**念出来是连在一起的一个词**。而且这个 `h1` 里还嵌了一个可点的返回按钮 —— 标题里套
控件,层级上说不通。

**建议:分区名留在 `h1`,当前条目降一级或移出标题;返回按钮从 `h1` 里拿出来。**

### 6. Stream 的主区域没有 `h1`,另外四个都有 ✅ 已修(MaterialPanel 的头衔升为 h1,念出 Source 的 kind)

其余四个路由的 `main` 里都有一个 `h1`。Stream 选中一条 Source 之后**一个标题都没有**。
键盘和读屏用户靠标题跳转,少一个就是少一个落脚点。

## 页面浮层的四种状态(2026-08-09,替身之下,9/9)⚠️ mock 标

最后一个没查过四态的面。真实长文档页面上,真 Host:

- **加载 ✓** —— 选区工具条在真实段落上出现,给的是真 Skill 列表(Simplify、Accurate
  transcription…),跑 Skill 时有可见的等待
- **内容 ✓** —— 答案就地出现,带引用角标、"N Sources" 和 Insert
- **出错 ✓** —— 问答失败当场把原话显示在页面上,不留转圈
- **内容过多 ✓ 修了一个真 bug** —— 9,135 字的答案原本让浮层**比窗口还高**,超出的部分
  够不着:浮层是 fixed 定位,没有任何东西能把它滚回来。加 `max-h-[60vh]` + 自己的滚动条
  (和应用里每个长列表一样)。这和 X8 是同一条规矩:**长东西给滚动条,不许向屏幕要它没有
  的高度。**

**Notion 与 Google Docs 上复验(在你自己的浏览器里,2026-08-09 10:2x)**:同一个 9,135 字
的答案,在真实 Notion(浮层 731px / 窗口 1158px)和真实 Google Doc(697px / 1102px)上
**竖横都在窗内、有自己的滚动条、页面没被撑宽**。这两处是碰浏览器界面必过的两站。

**又是三次探针错、零次产品错**:①"答案到了"拿整个 shadow root 的文本匹配,而那里面含着
注入的样式表 —— 它在一句 Tailwind 许可证注释上变绿;②改成只看叶子节点,而答案的标记不是
叶子;③选 Skill 的正则区分大小写,"Voice comment" 溜了进去,点下去开的是麦克风,我在等
一个根本没被请求的答案。现在断言的是答案**放在屏幕上的控件**(Insert + "N Sources")。

**那个"答案十来秒后消失"的观察,查清了,是我自己**(X28 撤销)。一次决定性测量:
`window.name` 还在、页面变量没了、`nav:"navigate"`、路径变成 `/stream` —— **整页被导航走了**。
干这件事的是我早先起的一个后台轮询:它的条件永远不会满足,于是每 20 秒跑一次
`build.mjs`,而那个脚本第一句就是 `goto('/stream')` —— **它和测试共用同一个标签页**。
杀掉之后同一段检查跑出 "answer stayed for 25s"。

写下来免得再犯:**与测试共用浏览器的后台轮询是一只看不见的第三只手。** 等待条件要么
写成不可能一直为真的形式,要么用独立标签页,而且任何 until 循环都要有出口 —— 我那个
条件在构建号往前走之后就再也不可能成立,它会一直转到会话结束。

## 复量一遍(2026-08-11,A2 结案)

六条当时都标了 ✅,但标记不是证据 —— 而且从那以后面板多了一个 Dictation tab、多了 Storybook、
多了 N2–N8 一整轮改动。所以**重新量了一次**,方法和第一轮一样:真浏览器、真工作区、真内容,
读计算样式,面板**四个 tab 逐个**量。

**先修了走查脚本本身。** `audit-ext.mjs` 只量"默认打开的那一屏"。面板改成默认开 Dictation
之后,它第一行 `document.querySelector('textarea')` 拿到 null,整个走查死在 `Illegal
invocation` —— **也就是说新加的那个面从来没被量过**。现在它按标签逐个切、逐个量,并把
"跨 tab 的字号集合"和"低于 24px 的点击目标"汇总成两行。**面板长出一个面,走查就得跟着长。**

### 复量抓到三条漏网的,都修了

| | 量到的 | 修法 |
|---|---|---|
| **#2 的余数** | `web/src/app/DocumentsRoute.tsx` 的 `<h2>{n} Sources</h2>` **字重仍是 400**,而另外四个 `h2` 都已经是 560 —— 和当初 Project 里那条是同一个字符串、同一个病,只修了一处 | 补 `font-[560]`,五个 `h2` 现在全是 560 |
| **#3 的新违规** | 对话里的引用角标 `[Source n]` 量到 **20×20 / 22×20**,低于 24px 地板。R13 之后它是产品里最常被点的东西之一 | 药方和当初那三处一样:**内边距做命中区、负外边距还回版面**。药丸视觉仍是 20px(它坐在 13px 正文行里),按钮盒子 24px,`-my-0.5` 把行高还回去 |
| **#3 的另一处** | Dictation 里"N recordings without words"那一整行是控件,量到 **16px 高** | 同上:`min-h-6 py-1 -my-1` |

### 复量确认还成立的

- **字号**:整个面板只有 **12px 和 13px** 两档 —— #4 定的"正文一个值、说明一个值"没有被这一轮新代码破坏
- **点击目标**:改完复量,**低于 24px 的一个都没有**(改之前是 5 个)
- **`faint` 令牌**:全树搜不到,#1 是真的删干净了
- **横向溢出**:面板四个 tab、语音条、选区条,全都没有
- **两个浮层**:VoiceBar 13px/400、SelectionBar 13px + 两个 560,和第一轮一致

### 说明白一处**没有**改的

`Menu.tsx` 的快捷键字母和 `ContextMenu.tsx` 的分组标题仍是 **11px**,是全产品仅剩的两处。
它们是 **X33** 特意照 Claude Code 的菜单做的(你确认过"标题行收成一行小灰字"),
**不是漏网,是一个和 #4 冲突的决定**。我没有自作主张推翻它 —— 要么留着(菜单 chrome 自成一档),
要么把这两处也拉到 12px,**这一句话是你的**。
