# N4 · 面板里的 Dictation:方案

你的原话,两段:

> "我们在 extension 的 panel 里面加入一个新的功能。简单起见,我们加一个新的 tab……
> 用户可以用语音输入,我们需要把这个页面里面的内容也作为 context 的一部分。我们只要显示那种可见内容。
> 我觉得是 HTML 里面的非 tag 里的东西……**你可以决定,你可以反驳我,可以用更好的办法。**
> transcribe 之后,我需要能有这个 audio,能有文本……可以 copy,而且我可以预定义一些 skill 来 transform
> 这个文本……同时我应该支持多个任务并行。"

> "还是把这个功能叫做 dictation……这个 UI 应该和 input 里面的 transcribe and insert 是类似的。
> 另外是一个非常好用简洁的 UI。**你可以来设计**,现在的 UI 有点太差了。"

**这份文件不实现界面。** 最后一节是要你回答的问题。
但里面有一件已经动手的事(第三节),因为它是一个正在发生的 bug,和要不要做 Dictation 无关。

## 一、已经在的零件 —— 五件事里有三件半不用重建

| 你要的 | 现在已经有 | 还缺什么 |
|---|---|---|
| ⑤ 多个任务并行 | **V3 已经做了一半**:收音是独占的、一瞬间的;落稿是后台的、可并发的。麦克风在你按下停止那一刻就还回来了 | 面板今天只显示一个**数字**("还有 n 段在转"),不是一个**列表**。每一段自己的音频、文本、失败,没有地方待 |
| ③ 音频和文本都在 | 每段语音都存成一条 Source:音频在 Host(`/v1/captures/{id}/audio`),文本在 Material 上,时长也记着(X31) | 面板里没有一个"这是我刚说的几段"的地方 |
| ④ 一键复制 | `Kept` 列表里的复制按钮,按一下变 ✓ —— 直接搬 | — |
| ④ Skill 改写 | `POST /v1/runs` 就是"拿一个 Skill 跑一段文字";`/adopt` 记录你是复制走了还是看看就关了 | 三处小改,见第五节 |
| ② 页面上下文 | **通道已经在**:转写请求里的 `nearby`,上限 1500 字,以引用块送进去,并且写明"只用来拼对名字,不是指令" | 面板里没有光标,所以"哪 1500 字"没有答案 —— 见第二节 |

所以这条任务真正的新东西只有两样:**一个 Dictation 界面**,和**页面上下文怎么取**。

## 二、② 页面上下文:我反驳你,并且带了数字

你说的是"把 HTML 里非 tag 的可见文字当 context"。**取文字这一步你是对的,送什么进去这一步我建议改。**

### 量出来的三个数

在真实页面 en.wikipedia.org/wiki/Speech_recognition 上跑现有的抽取器:

| | 数 |
|---|---|
| 抽出来的正文 | **60,000 字**(撞上限了),420 个段落 |
| 转写上下文的通道能装 | **1,500 字** |
| 也就是整页的 | **2.5%** |

更糟的是**哪个 2.5%**。这一页的头 1500 字是维基的维护模板:
"This article has multiple issues… needs more citations… may be too technical…" ——
整页最没用的那一段,恰好排在最前面。

### 我建议送的不是页面,是页面上的**生词**

同一页,把**整页**扫一遍,挑出不常见的词(句中大写的专名 + 全大写缩写,去掉停用词和月份),前 40 个:

> Speech, Recognition, IEEE, HMM, HMMs, Deng, ASR, Markov, Rabiner, Hinton,
> CTC, DTW, WER, Siri, Baker, Reddy, Microsoft, IBM …

**327 个字**。比 1500 字小到五分之一,却覆盖**整页**而不是开头 2.5%。
而且这 327 个字里的每一个,都正好是听写会听错的那一类:缩写、人名、术语。
1500 字的维护模板里,一个都没有。

### 为什么这不只是省字

转写这一步的模型有一个**已经发生过的**失败:给它五秒静音加一页上下文,
它会返回一句流利的、没有人说过的话("To calculate the standard deviation…")——
而这个产品会把那句话打进你的光标。代码里那条 `NOTHING_WAS_SAID` 就是为它写的。
**页面正文越长越像"素材",词表则不像** —— 词表没法被当成话说出来。
同理,整页正文里可能夹着"忽略以上指令"这种东西;一个词表夹不进去。

### 具体做法

1. 录音开始时,面板对当前标签页跑一次现有的 `readablePageText()`(**不新写抽取器**)。
2. 在扩展里从中挑词,拼成 `页面标题 + 术语表`,走**现有的** `nearby` 通道送出去。
3. Host 一行不用改:它已经会把这段引用起来、标明"只用来拼写"、并记进 `applied_context`,
   所以"它为什么这么听"事后仍然查得到。

**一个诚实的缺口:中文页面没有大写这个信号。** 中文页里能挑的只有夹在中文里的
拉丁词和缩写(比如"端对端(End-to-End,E2E)"),以及书名号引号里的词。
中文的专名(人名、公司名)这套办法挑不出来。所以中文页上这条会比英文页弱。
备选是中文页退回"标题 + 正文前 1500 字"。**这一条我列进第七节问你。**

## 三、顺手抓到的一个真 bug:中文页面,我们今天丢掉一半

查上一节的时候撞上的,**和 Dictation 无关,现在就在发生**:

`readablePageText()` 判断一段文字是不是正文的规矩是"**它得含一个空格**"
(注释写着"单个词是导航,不是正文")。**中文句子没有空格。**

在真实页面 zh.wikipedia.org/wiki/语音识别 上量:

| | 修之前 | 修之后 |
|---|---|---|
| 留下的段落 | 87 | **169** |
| 留下的字数 | 7,680 | **13,592** |
| 正文第一段("语音识别技术所涉及的领域包括…") | **丢了** | 在 |

丢掉的 362 块里,有 46 块是 40 字以上的正文段落。
这条抽取器**今天**服务两个功能:"Save this page"(存下来的中文页面少一半)
和面板对话的页面上下文(它读到的中文页面也少一半)。

**已经修了**,规矩改成:有空格算正文(拉丁文照旧),**或者**是中日韩泰这类不用空格分词的
文字且长过 12 个字。英文页面上零变化(699 段 → 699 段,一段不多一段不少),
中文页面上正文回来了、导航菜单仍然在外面。两条单元测试,并做了反事实:换回旧写法,两条立刻红。

## 四、①③④⑤ 的设计:Dictation 长什么样

### 规矩先说

- **和光标旁那条一套零件,不是第二套。** 同样的三个控件、同样的顺序、同样的两个键:
  **Enter 采纳,Esc 取消**。F10 已经把两条浮层收敛成一套,这里是同一条道理往面板延伸。
- **一行 = 一段录音。** 它从头到尾不换形状,只是长出东西来:先是计时,然后是播放器,然后是文字。
- **最新的在最上面。** 你刚说的那段,就是你要动的那段。
- **出事写在出事的那一行**,不写在顶上 —— 四段里坏了一段,顶上的一条错误说不出是哪一段。

### 一屏(按面板真实宽度 360 排)

```
┌────────────────────────────────────────┐
│  Chat  │  This page  │  Dictation      │
├────────────────────────────────────────┤
│ ● 0:14        [✓]  [✕]                 │  ← 正在录:勾=完成,叉=丢掉
├────────────────────────────────────────┤
│ ⟳ 转写中…  0:32                    [✕] │  ← 上一段还在路上,不挡着你录下一段
├────────────────────────────────────────┤
│ ▶ ──────────────────  0:47             │  ← 说完的:音频
│ 我们今天先把面板的信息架构定下来,然后再…  │     文本,两行,点开看全文
│ [⧉]   Into English   As Markdown   ⋯   │     复制 + 你预定义的 Skill
├────────────────────────────────────────┤
│ ▶ ──────  0:12                         │
│ ⚠ 模型没答应。录音留着 —— 再试一次        │  ← 失败也长在自己那一行
├────────────────────────────────────────┤
│              [ 🎤  Record ]             │  ← 只有一个按钮,钉在底部
└────────────────────────────────────────┘
```

### 每一件的落法

**① tab** —— 叫 `Dictation`,在 tab 条里。
**③ 音频和文本** —— 每一段说完就存成一条语音 Source(和今天面板里的语音走同一条路),
所以关掉面板再打开,它们还在;播放器用**已经共用**的 `Recording` 组件,面板和 Web 应用同一个。
**④ 复制** —— `⧉` 按一下变 ✓,和 `Kept` 列表里那颗一模一样。
**④ 改写** —— 一行里横排你标了 "Dictation" 的 Skill;超过两个进 `⋯`。
点一下跑一个 Run,结果**长在原文下面**,标着 Skill 的名字,**原文一个字不动**。
理由:音频是证据,转写是它的第一手文字。用翻译覆盖掉原文,等于把证据和结论混成一条。
**⑤ 并行** —— 麦克风只有一个,所以**同时只能录一段**;但按下勾的那一瞬间麦克风就还回来了,
下一段马上能开。这不是新写的,是 V3 已经成立的事(量过:3 秒的话等 3.4 秒,30 秒的话等 10.7 秒 ——
"锁着等转写"就是被这两个数字判掉的)。这里新写的只有**一个列表**,让每一段有自己的位置。

## 六、和 N1b 撞不撞车:我认为不撞

队列里那条备注写着"先定 IA 再加 tab"。**我现在认为不必等**,理由是主语:

panel-ia.md 数出面板里只有三个主语(这一页 / 这次的 scope / Logue 本身)。
**Dictation 是第四个** —— 它的主语是"我现在说的话",既不属于这一页,也不属于某个 Project。
所以无论 A 还是 B,它都是自己一格:

- 走 **A**(Chat 和 This page 合成一条流):面板剩 **2 个 tab** —— 这一页 · Dictation
- 走 **B**(tab 留着按主语重排):面板是 **4 个 tab** —— Chat · This page · Dictation · Settings

两种下面 Dictation 里面的东西**完全一样**。所以它可以先做,A/B 怎么定都不用返工。

## 七、要你回答的四个问题

1. **中文页面的上下文怎么办?** 英文页上"送生词表不送正文"我很确定(327 字 vs 1500 字的维护模板)。
   中文页上挑不出专名。**我建议:中文页送"标题 + 生词表(能挑到的拉丁词/缩写)+ 正文前 800 字"**,
   混着来,并且照样标成引用。你也可以说"中文页就送正文前 1500 字",我照做。

2. **Dictation 列表里该显示哪些段?** 我建议 **这个浏览器里最近说的,不分页面**(比如最近 20 段)——
   听写不是关于这一页的。另一个选择是只显示这一页上说的,那它就变成 "This page" 的一部分了。

3. **改写的结果要不要也存下来?** 我建议 **不默认存**:它是一个 Run,你复制走了就记一笔"用了",
   没用就是没用 —— 这正是这个产品判断一个 Skill 值不值的办法。
   你要的话我可以加一个"存成 Source"的按钮。

4. **先做哪个?** N4 现在不被 N1b 卡住(第六节),但队列里还有 **N2**(输入框里已经打好的字被语音丢掉)
   和 **N3**(自查"悄悄丢掉已有东西"的那一类)。**N2 是正在坏的**,而 N4 是新功能。
   **我建议 N2 → N3 → N4**,除非你要先看到 Dictation。
