我们需要从信息架构的角度重新组织。先 propose 一下,不要去做,需要我 confirm 才能继续去做。"

## 一、今天面板里到底有什么

从上到下,一件不漏:

| 层 | 里面有什么 | 主语是谁 |
|---|---|---|
| **头部**(`:867-896`) | 页面标题(小灰字)· "Open Logue web app" · ⚙ 服务器地址 | 一个是**这一页**,两个是 **Logue 本身** |
| **Tab 条**(`:899-922`) | Chat · This page(带计数)· Project | 一个**动作**、一个**对象**、一个**设置** |
| **Chat**(`:924-972`) | 错误条 · 等待中的录音 · 模型没连的提示 · 对话流(标题写着 "From this page")· 空状态 | 混着 **Logue 本身**和**这次对话** |
| **输入区**(`:776-857`) | 录音条 · 输入框 · "This page" 灰 chip · Project 下拉 · 🎤 · Ask | 混着 **scope** 和**动作** |
| **This page**(`:974-996`) | 错误条 · 等待中的录音(**又一次**)· "Save this page" · Kept 列表 | **这一页** |
| **一条 Source 展开后**(`:1396-1439`) | 改正文 · 页面定位/重锚 · Project 归属按钮 · tags | **一条 Source** |
| **Project**(`:997-1020`) | Project 下拉(**又一次**)· 折叠的 "About …":背景 + 词表 + Save | **一个 Project** |

一眼就能看出来的事:**主语有四个,而屏幕上的分组只有三个,还不是按主语分的。**

## 二、九个问题,按严重程度排

### 1. Project 这一个东西,面板里有三个入口,而且它同时干两件事(`:829-841`、`:1001-1013`、`:1400-1414`)

- 输入区的下拉:选的是**这次提问带哪个 Project 的上下文**
- Project tab 的下拉:选的是**我要看/改哪个 Project**
- Source 展开里的按钮组:改的是**这条 Source 属于哪些 Project**

三件事,三个地方,**共用同一个 `project` state**。所以在 Project tab 里换一个 Project 去看它的
词表,顺手就把下一次提问的上下文也换掉了 —— 没有任何地方告诉你这件事发生了。

**这是这个面板最严重的一条。** 它违反的是 design.md 第 7 条:同一个活儿,同一个控件;
反过来也成立 —— 同一个控件,不该干三个活儿。

### 2. Chat 和 This page 本来就是一条时间线,被切成了两个 tab(`:899-922`)

你在一页上做的事只有三种:**存下一段**、**说一句**、**它答一句**。三件事按时间发生在同一页上。
今天前一件在 "This page",后两件在 "Chat"。结果是:你刚存的那一段,和你紧接着问的那一句,
中间隔着一次点击 —— 而它们是同一件事的两半。

计数徽章更说明问题:"This page" 上挂着数字,"Chat" 上没有。**同一排 tab,一个是列表,一个是流。**

### 3. 主语说了两遍,而且都不在该在的位置(`:874`、`:899-922`)

页面标题在头部,用的是 `text-xs text-muted` —— 面板的**主语**被排成了最不起眼的一行字;
紧接着 tab 里又出现一个叫 "This page" 的东西。**一个主语,两个地方,两种字号。**

同一行里剩下的两个控件("Open Logue web app"、⚙)主语都是 Logue 本身,却占着面板最贵的一行。
按 design.md 第 6 条,一个静止的面板应该只显示你要动手的东西。

### 4. "From this page" 是对话流的标题,而隔壁 tab 就叫 "This page"(`:98`)

Chat tab 里,那条对话流的小标题写的是 "From this page"。**两个不同的东西共用一个名字。**
这一条在 X38 修完"一页一条对话"之后就更容易误读了:它现在确实是按页存的,
但它的名字应该说"这是对话",而不是重复隔壁 tab 的名字。

### 5. 等待中的录音,在两个 tab 里各画一遍(`:932`、`:977`)

同一个 `WaitingRecordings` 组件渲染两次。而它的内容(躺在盘上等 Host 的录音)
**既不属于这一页,也不属于这次对话** —— 它是全局队列。
一个东西同时住在两个地方,等于它没有家。

### 6. "出事了"有三种形状、三个位置(`:931`、`:976`、`:999`、`:941-952`、`:893-895`)

- `error` 在三个 tab 里各渲染一次
- "模型没连"只在 Chat tab 里出现 —— 可在 This page 里点 Save,一样会失败
- "连不上 Logue" 会在头部展开一个地址输入框

三层严重程度不同的坏消息,三种长相,三个地方。你在 This page tab 里的时候,
**不会知道模型没连**。

### 7. 输入区里有一个假控件(`:828`)

"This page" 那个圆角灰 chip 长得和旁边真能点的 Project 下拉一模一样,但它点不动 —— 它只是一句话。
design.md 第 4 条:chrome 里不要写解释句;第 3 条:控件的样子要说明它能不能按。

### 8. 面板最基本的动作之一("存这一页")藏在第二个 tab 里(`:978-982`)

要存这一页,先得离开 Chat。而 Chat 是默认那一屏(`:473`)。

### 9. 一条 Source 展开之后,四件事平铺成一坨(`:1396-1439`)

改正文、找回它在页面上的位置、改 Project 归属、改 tags —— 四件轻重完全不同的事
挤在一个灰块里,没有主次。design.md 第 5 条说的就是这个。
另外 Project tab 里那个 "About …" 是**折叠里再套折叠**:tab 已经是一层隐藏了。

## 三、我认为正确的分法

面板里的一切,主语只有三个:

| 主语 | 属于它的东西 |
|---|---|
| **这一页** | 存下的 Source、你说的、它答的、"存这一页" |
| **这次的 scope** | 哪个 Project 的上下文 |
| **Logue 本身** | 连到哪、模型好没好、几条录音在等、去 Web App |

**规矩:一个主语一个区,一个区一个位置,越全局的越往上、越安静。**

## 四、两个提案

### 提案 A(我推荐):一条流,scope 提到头部,全局收进状态条

```
┌──────────────────────────────────────────┐
│ ⚠ 只有出事才出现:模型没连 / 连不上 / 3 条录音在等 │  ← Logue 本身
├──────────────────────────────────────────┤
│ 页面标题                    [Project ▾]  ⋯ │  ← 主语一次 + scope 一次
├──────────────────────────────────────────┤
│                                          │
│   这一页上发生的事,一条流,倒序:            │
│     · 你存下的一段(带来源标、可展开)        │
│     · 你说的一句                           │
│     · 它答的一句(带 [Source n]、提案)      │
│                                          │
├──────────────────────────────────────────┤
│ [🔖 存这一页] [🎤]  问点什么…        [Ask] │
└──────────────────────────────────────────┘
```

六个动作:

1. **Chat 和 This page 合成一条流** —— 它们本来就是同一页上按时间发生的事。
   每行还是带来源标(存的 / 你说的 / 它答的),所以"这一页存了什么"没有丢,只是不再需要换 tab。
2. **Project 从内容区升到头部,只留一个** —— 它是 scope 不是内容。
   Project 自己的背景和词表进 ⋯ 菜单(它是设置)。
3. **Source 的 Project 归属留在那条 Source 上** —— 那是第三件事,和上面两个不是一回事,
   但它的控件要和头部那个**长得不一样**,否则又是一次"同一个控件三个活"。
4. **全局状态收进顶部状态条** —— 一处说尽:连不上、模型没连、录音在等。平时不占地方。
   "Open Logue web app" 和服务器地址进 ⋯。
5. **"存这一页"回到输入区** —— 存、说、问,三个都是"我现在要对这一页做的事",并排。
6. **删掉 "This page" 假 chip** —— scope 已经由头部说了。

**代价,先说清楚:**
- 一条流会比今天长。存了 20 段的页面,要往上滚才看得到早的。
  → 我的解法:流里给一个"只看存下的"筛子(一个开关,不是一个 tab)。
- 计数徽章没地方挂了。→ 挂在筛子上。

### 提案 B(保守):tab 留着,但按主语重排

不合并流,只修 1、3、5、6、7、8:

- Project 下拉**只留头部一个**,Project tab 改名 "Settings",里面只有 Project 的背景/词表
- 页面标题升成头部主行,"Open Logue web app" 和 ⚙ 进 ⋯
- 等待中的录音只在顶部状态条出现一次
- 错误/模型/连接三件事统一进状态条
- 假 chip 删掉
- "存这一页" 移进输入区

**好处:** 改动小,今天的肌肉记忆不变。
**坏处:** 第 2 条(存和问隔着一次点击)没有修 —— 而我认为那才是"信息架构有问题"最实在的一处。

## 五、我不建议动的

- **一页一条对话**(X38 刚定的)—— 不动。
- **提案要人点头才执行**(`:157-172`)—— 不动,这是这个产品的立身之本。
- **[Source n] 活引用和它的展开**(`:132-150`)—— 不动。
- **锚点的四个状态**(`:1214-1310`)—— 位置可以换,行为不动。
- **面板宽度 360** —— 不动。上面所有提案都是按 360 排的。

## 六、要你回答的三个问题

1. **A 还是 B?** —— 我推荐 **A**。理由:你说的是"从信息架构的角度重新组织",
   而 B 只是把东西摆正,没有改分法;真正的分法错误是第 2 条,只有 A 修它。
2. **Project 的编辑(背景 + 词表)进 ⋯ 菜单,你接受吗?** ——
   它是设置,不是这一页的内容。但它今天是一个平级 tab,降级之后会更难找一层。
3. **一条流里,"存下的" 和 "说的/答的" 要不要默认都显示?** ——
   我的建议:默认都显示,给一个"只看存下的"筛子。
   另一个选择是默认只显示对话,存下的要点筛子才出来 —— 更干净,但等于把 A 做成了 B。

答完这三个,我按 A(或 B)出一份逐屏的改动清单,再动手。
