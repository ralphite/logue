## 一、今天面板里到底有什么

从上到下,一件不漏:

| 层 | 里面有什么 | 主语是谁 |
|---|---|---|
| **头部**(`:1057-1085`) | 页面标题(小灰字)· "Open Logue" · ⚙ 服务器地址 | 一个是**这一页**,两个是 **Logue 本身** |
| **Tab 条**(`:1098-1120`) | **Dictation**(默认)· Chat · This page(带计数)· Project | 两个**动作**、一个**对象**、一个**设置** |
| **Dictation**(`:1194-1290`) | 等待中的录音 · 录音按钮 · 一条条听写,每条带音频、文字、可套 Skill | **你的嘴**,和这一页无关 |
| **Chat**(`:1121-1170`) | 错误条 · 模型没连的提示 · 对话流(标题写着 "From this page")· 空状态 | 混着 **Logue 本身**和**这次对话** |
| **输入区**(`:1010-1046`) | 录音条 · 输入框 · "This page" 灰 chip · Project 下拉 · 🎤 · Ask | 混着 **scope** 和**动作** |
| **This page**(`:1172-1193`) | 错误条 · "Save this page" · Kept 列表 | **这一页** |
| **一条 Source 展开后**(`:1667-1738`) | 改正文 · 页面定位/重锚 · Project 归属按钮 · tags | **一条 Source** |
| **Project**(`:1291-1315`) | Project 下拉(**又一次**)· 折叠的 "About …":背景 + 词表 + Save | **一个 Project** |

一眼就能看出来的事:**主语有五个,而屏幕上的分组有四个,还不是按主语分的。**

## 二、十个问题,按严重程度排

### 1. Project 这一个东西,面板里有三个入口,而且它同时干三件事(`:1017-1029`、`:1296-1308`、`:1692-1706`)

- 输入区的下拉:选的是**这次提问带哪个 Project 的上下文**
- Project tab 的下拉:选的是**我要看/改哪个 Project**
- Source 展开里的按钮组:改的是**这条 Source 属于哪些 Project**

三件事,三个地方,**前两个共用同一个 `project` state**。所以在 Project tab 里换一个 Project
去看它的词表,顺手就把下一次提问的上下文也换掉了 —— 没有任何地方告诉你这件事发生了。

**这是这个面板最严重的一条。** 它违反的是 design.md 第 7 条:同一个活儿,同一个控件;
反过来也成立 —— 同一个控件,不该干三个活儿。

### 2. Chat 和 This page 本来就是一条时间线,被切成了两个 tab(`:1098-1120`)

你在一页上做的事只有三种:**存下一段**、**说一句**、**它答一句**。三件事按时间发生在同一页上。
今天前一件在 "This page",后两件在 "Chat"。结果是:你刚存的那一段,和你紧接着问的那一句,
中间隔着一次点击 —— 而它们是同一件事的两半。

计数徽章更说明问题:四个 tab 里**只有 "This page" 挂着数字**。同一排里,一个是列表,其余是流。

### 2b. 【新】四个 tab 里有两个是"对着麦克风说话",靠一个 state 互相让路(`:575`、`:898`)

Dictation 和 Chat 都开录音,用的是**同一个 `useVoice`**;为了分清这一次录音归谁,代码里多了
一个 `speaking: "chat" | "dictation"`,并且 Enter/Esc 要先问它归谁再决定做什么。

**一个录音机、两个主人、外加一个裁判变量** —— 这是分法有问题时最典型的样子。
从用户那边看也一样:同样是按下麦克风说话,落在哪个 tab 决定它是"一条素材"还是"一句提问",
而这个决定是**在你说话之前**、通过选 tab 做出的。

### 3. 主语说了两遍,而且都不在该在的位置 —— 现在还更拧巴了(`:1073`、`:553`)

页面标题在头部,用的是 `text-xs text-muted` —— 面板的**主语**被排成了最不起眼的一行字;
紧接着 tab 里又出现一个叫 "This page" 的东西。**一个主语,两个地方,两种字号。**

**新情况:默认打开的是 Dictation**,而 Dictation 和"这一页"毫无关系。
于是面板打开时,最显眼的那一屏和头部那行页面标题**说的不是同一件事**。

同一行里剩下的两个控件("Open Logue"、⚙)主语都是 Logue 本身,却占着面板最贵的一行。

### 4. "From this page" 是对话流的标题,而隔壁 tab 就叫 "This page"(`:112`)

Chat tab 里,那条对话流的小标题写的是 "From this page"。**两个不同的东西共用一个名字。**
它现在确实是按页存的(X38),但它的名字应该说"这是对话",而不是重复隔壁 tab 的名字。

### ~~5. 等待中的录音,在两个 tab 里各画一遍~~ ✅ 已修(N5)

现在只在 Dictation 里出现一次,代码里写明了理由:"一条录音,一个能对它动手的地方"(`:1197-1207`)。
**这一条不用再管了。**

### 6. "出事了"有三种形状、三个位置(`:1127`、`:1174`、`:1293`、`:1140-1152`、`:1082-1084`)

- `error` 在三个 tab 里各渲染一次
- "模型没连"**只在 Chat tab 里出现** —— 可在 Dictation 里按录音、在 This page 里点 Save,一样会失败
- "连不上 Logue" 会在头部展开一个地址输入框

三层严重程度不同的坏消息,三种长相,三个地方。你在 Dictation 那一屏(**也就是打开面板默认看到的那一屏**)
**不会知道模型没连**。

### 7. 输入区里有一个假控件(`:1015`)

"This page" 那个圆角灰 chip 长得和旁边真能点的 Project 下拉一模一样,但它点不动 —— 它只是一句话。
design.md 第 4 条:chrome 里不要写解释句;第 3 条:控件的样子要说明它能不能按。

### 8. 面板最基本的动作之一("存这一页")藏在第三个 tab 里(`:1175-1180`)

要存这一页,先得离开默认那一屏,再离开 Chat。

### 9. 一条 Source 展开之后,四件事平铺成一坨(`:1667-1738`)

改正文、找回它在页面上的位置、改 Project 归属、改 tags —— 四件轻重完全不同的事
挤在一个灰块里,没有主次。design.md 第 5 条说的就是这个。
另外 Project tab 里那个 "About …" 是**折叠里再套折叠**:tab 已经是一层隐藏了。

### 10. 【新】默认那一屏不是"你打开面板要干的事",而是"最新做完的功能"(`:553`)

`useState<…>("dictation")` 上面的注释写着 "Dictation is what the panel is opened for"。
可面板有两个入口:**⌘⇧L**(我要看这一页有什么)和 **⌘⇧K**(我要说句话)。
⌘⇧K 已经会把 tab 切到 Chat(`:658`),所以 Dictation 当默认,服务的是**第三种**、
没有快捷键的进入方式。**默认屏该由入口决定,不该由排期决定。**

## 三、我认为正确的分法

面板里的一切,主语只有四个:

| 主语 | 属于它的东西 |
|---|---|
| **这一页** | 存下的 Source、你说的、它答的、"存这一页" |
| **你的嘴** | 听写:录下来的音频和它的文字,和任何页面都无关 |
| **这次的 scope** | 哪个 Project 的上下文 |
| **Logue 本身** | 连到哪、模型好没好、几条录音没变成字、去 Web App |

**规矩:一个主语一个区,一个区一个位置,越全局的越往上、越安静。**

## 四、两个提案

### 提案 A(我推荐):四个 tab 收成两个,scope 提到头部,全局收进状态条

```
┌──────────────────────────────────────────┐
│ ⚠ 只有出事才出现:模型没连 / 连不上 / 3 条没成字 │  ← Logue 本身,四屏共用
├──────────────────────────────────────────┤
│ 页面标题                    [Project ▾]  ⋯ │  ← 主语一次 + scope 一次
├──────────────────────────────────────────┤
│  这一页  |  听写                           │  ← 两个 tab,两个主语
├──────────────────────────────────────────┤
│                                          │
│   这一页上发生的事,一条流,倒序:            │
│     · 你存下的一段(带来源标、可展开)        │
│     · 你说的一句 / 它答的一句(带 [Source n])│
│                                          │
├──────────────────────────────────────────┤
│ [🔖 存这一页] [🎤]  问点什么…        [Ask] │
└──────────────────────────────────────────┘
```

七个动作:

1. **Chat 和 This page 合成一条流** —— 它们本来就是同一页上按时间发生的事。
   每行还是带来源标(存的 / 你说的 / 它答的),所以"这一页存了什么"没有丢,只是不再需要换 tab。
2. **Dictation 留成第二个 tab,不动它的内容** —— 它的主语是"你的嘴",确实不属于这一页。
   但**它不该是默认**:默认回到"这一页"(见第 10 条)。
3. **Project 从内容区升到头部,只留一个** —— 它是 scope 不是内容。
   Project 自己的背景和词表进 ⋯ 菜单(它是设置),Project tab 消失。
4. **Source 的 Project 归属留在那条 Source 上** —— 那是第三件事,但它的控件要和头部那个
   **长得不一样**,否则又是一次"同一个控件三个活"。
5. **全局状态收进顶部状态条** —— 一处说尽:连不上、模型没连、录音没成字。平时不占地方,
   **四屏共用**(今天"模型没连"只有 Chat 看得到)。"Open Logue" 和服务器地址进 ⋯。
6. **"存这一页"回到输入区** —— 存、说、问,三个都是"我现在要对这一页做的事",并排。
7. **删掉 "This page" 假 chip** —— scope 已经由头部说了。

**代价,先说清楚:**
- 一条流会比今天长。存了 20 段的页面,要往上滚才看得到早的。
  → 我的解法:流里给一个"只看存下的"筛子(一个开关,不是一个 tab)。
- 计数徽章没地方挂了。→ 挂在筛子上。
- **Dictation 从默认变成第二个 tab**,如果你现在主要就是拿它当听写器用,这一条你会立刻感觉到。
  → 那说明默认该由**你最常按哪个快捷键**决定,不是由我猜。这也是下面第 3 个问题。

### 提案 B(保守):四个 tab 留着,但按主语重排

不合并流,只修 1、3、6、7、8、10:

- Project 下拉**只留头部一个**,Project tab 改名 "Settings",里面只有 Project 的背景/词表
- 页面标题升成头部主行,"Open Logue" 和 ⚙ 进 ⋯
- 错误/模型/连接三件事统一进顶部状态条,**四个 tab 都看得见**
- 假 chip 删掉
- "存这一页" 移进输入区
- 默认那一屏按入口决定,不按排期决定

**好处:** 改动小,今天的肌肉记忆不变。
**坏处:** 第 2 条(存和问隔着一次点击)和第 2b 条(两个 tab 抢一个录音机)都没有修 ——
而我认为那两条才是"信息架构有问题"最实在的地方。

## 五、我不建议动的

- **一页一条对话**(X38)—— 不动。
- **Dictation 里那一条条听写本身**(N4:音频 + 文字 + 套 Skill + lineage)—— 内容一个字不动,
  只讨论它在哪一层、是不是默认。
- **提案要人点头才执行**(`:171-186`)—— 不动,这是这个产品的立身之本。
- **[Source n] 活引用和它的展开**(`:146-164`)—— 不动。
- **锚点的四个状态**(`:1505-1600`)—— 位置可以换,行为不动。
- **面板宽度 360** —— 不动。上面所有提案都是按 360 排的。

## 六、要你回答的三个问题

1. **A 还是 B?** —— 我推荐 **A**。理由:你说的是"从信息架构的角度重新组织",
   而 B 只是把东西摆正,没有改分法;真正的分法错误是第 2 条和第 2b 条,只有 A 修它们。
2. **Project 的编辑(背景 + 词表)进 ⋯ 菜单,你接受吗?** ——
   它是设置,不是这一页的内容。但它今天是一个平级 tab,降级之后会更难找一层。
3. **打开面板,你最想先看到哪一屏?** —— 今天是 Dictation。
   我的建议是**"这一页"**,因为 ⌘⇧K 已经会跳去说话那一屏。
   但这个答案只在你脑子里:**你按 ⌘⇧L 的时候,心里想的是"这一页有什么",还是"我要说句话"?**

答完这三个,我按 A(或 B)出一份逐屏的改动清单,再动手。
