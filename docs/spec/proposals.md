## R12 · 竞品扫描:他们做到哪了,我们缺什么

看了四类:随处语音输入(Wispr Flow、superwhisper)、文档里的 AI(Notion)、
带出处的知识管理(PKM 那一类)。**功能清单是菜单不是命令** —— 下面每一条我都标了
"该不该拿",不值得的说明为什么。

### 语音输入这一类

| 他们有 | 我们 | 该不该拿 |
|---|---|---|
| **个人词典会自己长**:你说过的特殊词自动进词典 | 有词表,但只能手填 | **该** —— 就是 F5,见下 |
| **上下文感知**:读当前 app / 屏幕内容来提高准确度 | 有(光标附近文本已经送进转写) | 已有 |
| **按场景切换模式**:邮件、聊天、纯听写各一套 prompt | 有(Skill + 默认槽位) | 已有,而且我们的更可编辑 |
| **语音快捷短语**:说一个代号,展开成一整段 | 无 | **不拿** —— 这是文本扩展,不是这个产品要解决的问题 |
| **团队共享词典** | 无 | **不拿** —— 你这是单机、本地优先的产品 |
| **跨设备同步词典** | 无 | **不拿(现在)** —— 与"一台机器一个 Logue"冲突 |

### Notion 这一类(你点名要看的)

2026 年 Notion 的动作集中在**代理**上:自定义 Agent 可以按计划或事件自动跑;
会议记录做完能直接触发一个 Agent;Agent 能生成能交互的 HTML 块。

| 他们有 | 我们 | 该不该拿 |
|---|---|---|
| **会议记录的自定义指令**:你规定摘要的分节、语气、长度 | Skill 就是这个 | 已有 |
| **事件触发的 Agent**:某件事做完自动跑下一步 | 无 | **也许** —— 见 F3 的开放问题 |
| **Agent 自动改工作区**(更新状态、发帖、建工单) | 无,而且**故意没有** | **不拿** —— 见下面那条红线 |
| **跨页面 AI 块** | 无 | **不拿** —— 我们的对应物是 Source 引用,更硬 |

**一条红线,先说清楚。** Notion 的 Agent 敢自动改东西,是因为它不承诺出处。
Logue 的立身之本是"每一句生成都站在能点进去的 Source 上"。**任何"AI 自己动手改了什么"
的功能,都要先回答它怎么留痕。** 这不是保守,这是这个产品和 Notion 的区别本身。

### 带出处的知识管理这一类

这一类今年的共识和我们已经在做的完全一致:**没有引用的 AI 会自信地说错**,
带引用的至少能查。有工具专门做"某个事实什么时候变的、从哪来的"。

我们已经有的:Source 冻结、Skill 版本、采用与撤销、血缘视图。**这一块我们不落后。**
真正缺的一条:**时间维度** —— 一条 Source 说的东西后来被另一条推翻了,现在没有任何地方
表达"这条过时了"。**值得单开一条任务,但不急。**

## F5 · 用历史输入把转写越修越准

你的原话:"historical user inputs with high quality should be used to improve
transcription. e.g. frequent special words/names should be correct."

### 现在有什么

三块地基已经在跑:

1. **Project 词表**(`transcription_profile.vocabulary.terms`)—— Host 转写时就在读
2. **光标附近的页面文字** —— 已经当临时词汇送进 prompt
3. **你手动纠错的记录**(`voice_profile.corrections`,上限 40)—— 同一个词再纠一次会替换而不是叠加

缺的是把它们连起来那一步:**从历史里自动挑出该记住的词。**

### 提议:三档,按"人碰过没有"分

**这是整套方案的核心判断** —— 学什么不该看频次,该看**有没有人为它做过一个决定**。

| 档 | 信号 | 怎么处理 |
|---|---|---|
| **一档:直接学** | 你**手动改过**的词(纠错记录) | 自动进词表,不问你。你已经用行动说过"是这个词不是那个词",再问一遍是废话 |
| **二档:先问你** | 你**亲手打进**文档/Source 的专有名词,出现 ≥3 次,而转写从来没拼对过 | 攒着,在 Settings 里给一个"要不要记住这些词"的列表,一次批准或逐个批准 |
| **三档:永不学** | 只在**转写结果**里频繁出现的词 | 不学。转写把某个名字连错十次,它就在转写里出现了十次 —— 按频次学等于把口误和听错学成规矩 |

三档是这套方案里最重要的一条。竞品的"自动学你说的词"听起来很好,
**但它学的是模型自己的输出**,错了就自我固化。我们有一个它们没有的东西:
**你亲手写的文档**。那才是"你确实是这么拼的"的证据。

### 你要回答的四个问题

1. **什么算"高质量"输入?** —— 我的答案是上面的三档:纠错=一档,手写文档里的专名=二档,
   转写自身=三档不学。**你同意这个划法吗?**
2. **词是自动进表还是要你点头?** —— 我的答案:一档自动,二档要你点头。
   **你要不要连一档也先问一遍?**
3. **词表属于一个 Project 还是全局?** —— 我的答案:**两层**。录音时带了 Project 就学进那个
   Project;没带就进全局表。转写时全局在下、Project 在上,Project 说了算。
   **可以吗?**
4. **怎么不把口误学进去,学错了怎么撤?** —— 我的答案:三档规则挡住绝大部分;
   另外**词表是一个能看能改的列表**,每个学来的词都写明出处("你在 8 月 9 日改过这个词")
   和删除入口。**没有任何词是悄悄学进去的。** 这一条我建议不商量。

## F3 · ⌘⇧K:开面板、开录音,说完进对话

你的原话已经把行为定死了:"cmd+shift+k opens the ext panel and starts voice
recording, esc to cancel and enter to accept. msg send to chat. in chat we can use
existing skills configured (such as translate, add to project etc). the chat should
use a llm agent that we can control."

### 已经在的零件

这一轮刚落地的几件正好是它的地基:

- **面板里已经有对话流**(F1):两条消息,"跑了什么"+"结果"。加更多消息是同一个组件
- **右键菜单已经能挂 Skill**(F1):`contexts` 决定哪些 Skill 出现在哪
- **⌘⇧L 已经真正开关面板**(F2):⌘⇧K 走同一条路,多一步"顺手开始录音"
- **录音有计时、有上限、失败能重试**(F4)

### 提议的功能清单

**一定要有(你已经说明的):**

1. ⌘⇧K 一下:面板打开 **并且立刻开始录音** —— 一个动作,不是两个
2. 录音中:**Esc 取消,Enter 采纳**。和浮层里的键一致,不再学一套
3. 采纳后:那段话**作为一条你的消息**进入对话,看得见你说了什么
4. 对话里能**调用已经配置好的 Skill**:翻译、加进某个 Project、起草……
   哪些 Skill 出现,读 Skill 自己的 `contexts`(和 F1 同一套,不再有第二份清单)
5. 背后是一个**我们自己能控制的 agent**:prompt、能调用哪些工具、每一步做了什么,
   都在我们手里,不是一次性的黑箱 prompt

**我建议加上(理由在括号里):**

6. **每条产出都带 Source 引用**,和别处一样(不带引用的对话会把这个产品变成又一个聊天框)
7. **对话记录进工作区**,不是只活在面板里(说过的话不该因为关了面板就没了)
8. **agent 的每一次工具调用都显示出来** —— "我读了这一页"/"我把它加进了 Mobile research"
   (一个偷偷改了东西的 agent,和这个产品的立身之本冲突)
9. **改动要你点头才生效**,至少默认如此(见下面的开放问题)

**我建议不加:**

- ~~自动触发的 Agent(按计划、按事件自己跑)~~ —— Notion 有,但那是团队协作产品的需求;
  在一个单人本地工具里,"我不在的时候它自己动了"是恐怖故事不是功能
- ~~多轮长对话记忆~~ —— 先做单轮到几轮。你要的是"说一句、它办一件",不是聊天机器人

### 你要回答的两个问题

1. **agent 能不能不问就改东西?** 比如你说"把这个加进 Mobile research",
   它是直接加,还是先给你看"我要加这个,确认吗"?
   **我的建议:能读的直接读,能写的一律先问** —— 至少第一版。
   写操作一旦默认放行,这个产品和 Notion 的差别就只剩下它跑在本地。
2. **对话的产出算不算 Source?** 我倾向算:它是你说的话加上模型的回答,
   两样都值得留。但这会让 Stream 里多出一类东西。**你要不要它出现在 Stream 里?**
