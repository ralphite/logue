# Logue V1 历史设计：Skills 与生成

> 本文件描述已发布 V1，已被 V2 整体产品设计覆盖。当前权威稿见 [`logue-ai-product-positioning-2026-08-04.md`](./logue-ai-product-positioning-2026-08-04.md)。

状态：当前目标设计，不是已完成证据。

## 设计判断

- 沿用 Logue 已有的安静一级导航、内容优先编辑和自动保存，不新造一个重型“Skill 管理后台”。
- 一级名称使用“生成”，因为结果可以是短回复、消息、QA、资料或文档；不再使用“成果”。
- Skill 是可编辑 Prompt 与结构化能力的合成对象，参考 Vibedoc 的 doc-backed Prompt；但 Logue 还必须记录项目、来源、运行结果和 Extension 插入目标。
- 转写、后台整理与用户主动生成共用 Skill 模型，但使用不同任务类型和权限边界。

## 界面结构

### Web 生成

- 共享常驻一级导航。
- 二级栏只保留 Documents 与 Skills 的切换和各自列表。
- 主区新生成仅保留 Skill、本次意图和来源摘要。默认 Skill 与当前项目被自动选中；用户需要时才展开更多来源。
- 运行后原地显示结果：短文本可编辑/复制，QA 按问答显示，文档进入 Notion 式编辑器。

### Skill 编辑

- 左侧 Skill 列表，右侧一个类文档编辑页。
- 标题是 Skill 名，其下是一句目的和大块指令。
- 紧凑设置只包含任务类型、输出形态、上下文范围与出现表面。每项修改自动保存。
- 系统 Skill 可“复制并编辑”；用户 Skill 可禁用或删除。删除前显示对默认任务的影响，不静默改用其他 Skill。

### Extension

- 输入框聚焦时默认只显示一个极小麦克风入口；生成只在渐进披露后出现。麦克风仍是单步开始，不经过 Skill 选择。
- 生成默认直接使用已设定 Skill；切换 Skill 是次要动作。面板仅显示本次意图、可检查的来源摘要和生成结果。
- 结果可编辑；主动作“插入”，次动作“取消”。不按 Enter、不点击发送。

## 稳定数据边界

- `Skill`: 当前可编辑定义与 revision。
- `SkillRun`: 引用不可变的 Skill 版本摘要、用户意图、实际 source IDs、实际 Context、输出类型、原始结果、采用后结果和执行状态。
- `Material`: 保持可追溯输入/派生内容，可由 SkillRun 创建，但不因 Skill 修改而被追溯改写。
- `Document`: 是持久可编辑输出之一，不是所有 SkillRun 的强制容器。

## 风险与处理

- 低置信度自动整理：先保存资料，标记“需要确认”；不阻塞当前输入。
- 生成来源不足：结果允许明确表达“缺少信息”，不自动扩大整库 Context。
- 宿主输入目标消失：生成记录仍保留，提供复制或重新聚焦后插入。
- Skill 指令被恶意网页文本影响：页面和资料始终作为未信任引用，不能改写 Skill 指令或工具边界。

## 首个可验证闭环

1. 用户复制默认“生成回复” Skill，修改其语气指令并设为 Extension 默认。
2. 在真实聊天 Web 页聚焦输入框，点“生成”，基于一条显式关联资料生成短回复。
3. 编辑结果并插入输入框；页面不自动发送。
4. Web 生成历史可查看同一运行的 Skill 版本、来源、原始结果和采用结果。
