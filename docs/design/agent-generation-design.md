# Agent 与生成产品设计

状态：当前目标设计，不是已完成证据。

## 设计判断

- 沿用 Logue 已有的安静一级导航、内容优先编辑和自动保存，不新造一个重型“Agent 管理后台”。
- 一级名称使用“生成”，因为结果可以是短回复、消息、QA、资料或文档；不再使用“成果”。
- Agent 是可编辑 Prompt 与结构化能力的合成对象，参考 Vibedoc 的 doc-backed Agent；但 Logue 还必须记录项目、来源、运行结果和 Extension 插入目标。
- 转写、后台整理与用户主动生成共用 Agent 模型，但使用不同任务类型和权限边界。

## 界面结构

### Web 生成

- 共享常驻一级导航。
- 二级栏顶部是“新生成”，下方是最近运行/持久结果，底部是“管理 Agent”。
- 主区新生成仅保留 Agent、本次意图和来源摘要。默认 Agent 与当前项目被自动选中；用户需要时才展开更多来源。
- 运行后原地显示结果：短文本可编辑/复制，QA 按问答显示，文档进入 Notion 式编辑器。

### Agent 编辑

- 左侧 Agent 列表，右侧一个类文档编辑页。
- 标题是 Agent 名，其下是一句目的和大块指令。
- 紧凑设置只包含任务类型、输出形态、上下文范围与出现表面。每项修改自动保存。
- 系统 Agent 可“复制并编辑”；用户 Agent 可禁用或删除。删除前显示对默认任务的影响，不静默改用其他 Agent。

### Extension

- 输入框聚焦时只显示两个极小独立入口：麦克风和生成。麦克风仍是单步开始，不经过 Agent 选择。
- 生成默认直接使用已设定 Agent；切换 Agent 是次要动作。面板仅显示本次意图、可检查的来源摘要和生成结果。
- 结果可编辑；主动作“插入”，次动作“取消”。不按 Enter、不点击发送。

## 稳定数据边界

- `Agent`: 当前可编辑定义与 revision。
- `AgentRun`: 引用不可变的 Agent 版本摘要、用户意图、实际 source IDs、实际 Context、输出类型、原始结果、采用后结果和执行状态。
- `Material`: 保持可追溯输入/派生内容，可由 AgentRun 创建，但不因 Agent 修改而被追溯改写。
- `Document`: 是持久可编辑输出之一，不是所有 AgentRun 的强制容器。

## 风险与处理

- 低置信度自动整理：先保存资料，标记“需要确认”；不阻塞当前输入。
- 生成来源不足：结果允许明确表达“缺少信息”，不自动扩大整库 Context。
- 宿主输入目标消失：生成记录仍保留，提供复制或重新聚焦后插入。
- Agent 指令被恶意网页文本影响：页面和资料始终作为未信任引用，不能改写 Agent 指令或工具边界。

## 首个可验证闭环

1. 用户复制默认“生成回复” Agent，修改其语气指令并设为 Extension 默认。
2. 在真实聊天 Web 页聚焦输入框，点“生成”，基于一条显式关联资料生成短回复。
3. 编辑结果并插入输入框；页面不自动发送。
4. Web 生成历史可查看同一运行的 Agent 版本、来源、原始结果和采用结果。
