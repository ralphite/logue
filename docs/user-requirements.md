# Logue 用户原始要求（事实来源）

本文件只记录用户在原会话与当前会话中明确表达的意图。产品规格、Mock 和 Agent 生成的建议不能覆盖这里的要求；发生冲突时，以较新的用户纠正为准。

## 核心目标

- 做一个非常好用、完成度高、真正解决核心任务的工具；UI/UX 具体方案由产品设计判断，用户要求的是质量，不是某一种固定交互。
- 优先实现高价值输入、采集、沉淀与复用闭环；删除头像、泛统计、泛 Agent 建议等低价值 UI。
- 极简主义是全局设计原则：屏幕上的每个元素都必须能说明其价值。正常运行、已连接、成功等不需要用户处理的状态不显示；只有问题或需要行动时才出现。操作文案不重复上下文，例如明确是复制动作时只显示 `Copy`。
- 同级选项的默认、hover、focus、selected 状态必须使用相同组件骨架和背景范围，不能出现相同语义却尺寸、圆角、对齐或命中区不一致。所有前端实现都应以资深 UI 设计师视角主动反思并消除这种明显破损。
- 居中内容必须使用统一且有理由的宽度体系，不能在相邻功能中随意出现 760/820/860 等不同宽度。文档、项目详情、设置、生成与 Skill 编辑使用共享 page/editor/reading axes 并保证 header 和正文垂直对齐；只有高密度列表可使用明确的宽列。
- 整体产品像 Notion 一样简洁、安静、可编辑；生成结果使用 Notion 式文档列表与文档编辑体验。
- 桌面/平板左侧栏应像 ChatGPT.com 一样可以折叠，折叠前后都保持稳定、易懂和高质量；移动端不能因此退化。
- Web App 中至少三处竖向分栏边界都应可拖拽调整宽度，并使用一致的视觉与交互；不能出现某些边界可拖、某些只是静态线条的混乱状态。
- Web App UI 统一使用英文；对应 Web 代码也使用英文命名、注释、无障碍文案与测试描述。
- 左侧主导航展开/折叠时，图标的水平位置必须完全稳定，不能因 padding、居中方式或动画发生跳动；交互质量参考 ChatGPT.com 的真实侧栏。
- 用户先提出过“品牌图标原位替换 collapse icon”，随后明确否定该设计；当前要求以 Notion 为准：收起控件位于 Sidebar 右侧并只在 hover/focus-within 时出现。展开/折叠时一级图标位置仍保持不动，并支持键盘操作。
- 所有右侧可调整面板都必须能扩展到工作区 100% 的剩余可用宽度，不能被固定 `max-width` 卡住；窄屏直接使用全部可用空间。
- “生成”导航只保留 Documents 和 Skills。点击两行只切换下方列表；每行最右独立加号分别进入生成新文档与创建新 Skill。删除重复的顶部加号和 `New`，Documents/Skills 切换时保持同一布局骨架。
- 网页语音输入默认不能比 ChatGPT 原生语音输入更复杂。

## 明确功能

- Logue 仍是单用户部署，但服务与客户端可以分离：Go/Web/API 可运行在局域网 Linux 主机，MacBook Chrome Extension 与 Web App 通过防火墙分配、可能变化但用户已知的域名访问；MacBook 不需要本机启动服务。Gemini Key 仍只存在于服务端环境。
- 内容永久保存，除非用户明确手动删除。
- 在网页输入框中快速使用语音或文字；不是在应用内放一个孤立 textarea。
- 选中网页文字后，可通过右键快速保存为原始资料，可无项目，也可关联项目和 Tag。
- 选区流程支持文字或语音批注；已保存资料也能继续追加批注或指令。
- 区分不同输入来源，保存原始音频、处理结果、最终采用文字、来源和派生关系。
- 一条资料可属于多个项目；项目包含资料、项目知识和文档。
- 输入保存后，系统先在后台自动归并到项目并加入 Tag；高置信度结果不打扰用户，只有有疑问、不确定时才高亮请用户复核。
- 用户对任何一条输入资料都可以修改内容、项目和 Tag；这些能力属于事后整理，不得进入录音主流程。
- 一级产品对象使用资料流、项目、生成；不使用 Inbox。Context 是执行时装配的输入，不是用户难以理解的一级页面。
- 产品必须支持多个可由用户定制的处理能力：一个可用于转写，一个可用于资料加 Tag/归项目，其他能力可基于原始资料生成新内容。当前只有 Prompt/指令编辑的用户对象称为 Skills；只有真正自主运行的对象才称为 Agents。
- “成果”不是合格功能名；统一使用“生成”。生成结果不只是文档，还可以是短消息、回复、QA 或其他可采用内容。
- 可定制 Skills 必须能在 Web 和 Extension 中使用。在 Web 聊天输入框等网页里，用户除了语音输入，还可基于相关项目/资料生成回复并插入，但不自动发送。
- 参照用户实际 Notion 中的 Skills：用户要能创建、编辑和配置文本变换 Skill；在 Logue Document 中选中文本时，出现类似 Notion 的轻量选区菜单/输入入口，可直接调用某个 Skill（如翻译、缩写）并更新所选文字。Extension 也应把同一能力带到任意可编辑网页目标；对静态网页内容不得假装可直接改写。必须先真实使用 Notion 当前功能，按其观察到的交互模式实现，而不是凭记忆猜测。
- Logue Web App 自己也是 Extension 的使用场景；不能因为页面是 Logue 就整体禁用 Extension，仍需在其真实输入目标旁提供相同能力。
- 其他 Agent 可通过只读文件或 API 使用项目内容，并通过受控 API 把带来源的分析结果写回。
- 动态 Context / Glossary 应利用个人信息、项目知识、近期和最终采用表达，并避免错误强化。

## 语音交互的最新明确要求

用户最新明确纠正：Extension 是极简语音输入器，不能是迷你表单，不能比直接键盘输入更复杂。此前“停止后进入可编辑审阅”已经被更新要求覆盖，不得继续实现。

强制流程：

1. 只有某一个真实网页输入目标当前聚焦时，额外语音 launcher 才显示；它只负责该输入目标旁的原位语音输入，不打开或 toggle Chrome 原生 Side Panel；
2. 点击 launcher 一次即在原位开始录音；工具栏、右键菜单与 `Cmd/Ctrl+Shift+L` 才打开或关闭 Chrome 原生 Side Panel；
3. 录音态只有“停止并插入”和“取消”；
4. “停止并插入”自动转写、自动保存、自动插入，不出现转写检查、项目、Tag、参考详情或归档设置；
5. “取消”立即结束且不保存、不插入；
6. 项目、Tag、纠错和其它整理全部放到事后，或由系统后台自动完成；
7. 必须提供快捷键直接开始/结束这条链路；
8. 永不自动提交宿主网页表单；保存仍先于插入，失败可恢复且不得重复插入或重复保存。

## 当前会话新增的交付要求

- React + TypeScript + Tailwind CSS + Storybook；Go 后端；Gemini 使用终端环境变量。
- 使用真实浏览器/电脑测试 Extension 与 Web App；创建或下载真实音频做 E2E。
- 转写质量至少达到同工作区的 `../prototypes/vibedoc`，并可通过环境变量配置模型、技能和上下文上限。
- 用多种输入、多个项目和多个生成文档证明价值，并保留数据供复查；最终保持服务器运行。
- 所有可见状态完整；最终由独立代理重新核对全部用户输入和交付目标。
- 使用 ChatGPT.com 对真实产品截图做 UI/UX 盲审并持续改进，直到继续修改的增益有限。
- 对照 Notion 和当前直接/相邻竞品审查信息架构、核心流程、编辑体验和差异化能力；不能只做视觉换皮。Mobile 曾在此范围内，现按最新要求降为非当前优先。
- 使用 fresh-context 第三方 Agent 独立审查全部目标；未达到目标时继续实现，不得把审查报告本身当作完成。
- 把全部用户要求、项目目标、完成条件和错误解释明确写进项目文件，并作为后续实现的强制约束。
- 每小时在当前任务中自动重新审查一次目标完成度，并在未完成时继续最高价值工作。
- 对全部历史 bug 与 feature request 做独立复核，维护逐项进度和未完成列表；明显且无歧义的设计问题主动修复，不确定项单列给用户 review。
- 先完成缺失实现，再做与风险相称的测试；不能在大量核心功能缺失时用低价值测试消耗主要时间。
- 用户曾要求提供真实产品截图、同一局域网手机访问和完整手机体验；最新纠正是 Mobile 当前不优先，也不阻塞桌面 Web、Extension、Storybook、legacy 清理、Release 和设计终审。
- 远端 `https://github.com/ralphite/logue` 的旧实现已经完全废弃，允许删除并放弃远端既有内容；当前 Logue 必须完整替换它，成为唯一代码来源。
- 必须创建 GitHub Release，并提供一个可复制的一行 `curl URL | shell` 安装命令；用户不应手动 clone 或构建。
- 同一安装命令既能全新安装，也能覆盖已有 Logue 程序；覆盖前安全停止旧服务，覆盖后自动启动新服务，已有 data 数据绝不能覆盖或删除。
- 安装过程必须询问用户是否加入机器开机自动启动，同时支持非交互环境的显式选择；安装完成必须验证服务真正启动并提供访问地址。
- Release、仓库、安装日志与配置不能包含 Gemini API Key、真实用户资料或 QA 私有音频。
- Release 必须等所有当前需求、真实验收、设计终审、Storybook 状态覆盖与安全数据整理均完成后再做；不能为了发布跳过未完成功能。

## 本任务最新明确纠正

- 当前仍只有一个用户且不需要历史版本兼容；最新部署允许 Linux 服务主机与 MacBook Chrome 客户端分离。真实服务主机上的当前数据必须保护，隔离验收机器可视为没有数据。除非用户以后明确要求兼容，禁止 legacy migration、旧字段/路由 alias、旧文案 fallback、双格式 parser、兼容 fixture/test 和废弃默认数据。当前数据需要变化时只做一次有备份、可验证的数据更新，随后删除迁移代码。
- 当前可复用能力只有 Prompt/指令编辑，因此用户界面名称应为 `Skills`，不是 `Agents`。只有未来具备 trigger、tools、permissions 和 runs 的自主能力才称为 Agents。
- Extension 当前产品架构是 Chrome 原生 Side Panel，不继续保留旧网页浮层作为兼容路径。Toolbar 与 `Cmd+Shift+L` / `Ctrl+Shift+L` 都必须可靠 toggle；关闭、切页或 Side Panel 消失时必须停止录音并忽略迟到回调。
- Side Panel 的左/右位置及原生 pin/unpin 由 Chrome 控制；Logue 不提供自己的侧位或 unpin 设置，也不能删除 Chrome 原生按钮。
- 原生 Side Panel 同时支持选区、当前页面和网页输入目标。右键保留直接保存，并增加在 Side Panel 查看；无输入框时也能录音保存页面资料。
- Side Panel 快捷键只在自身获得焦点且用户不在编辑控件中时生效：`R` 录音、`Enter` 停止并转写、`Esc` 取消；不得抢占 IME、宿主表单或普通文本编辑。
- 左侧栏折叠采用最新 Notion 参照：栏右侧的收起控件只在 Sidebar hover/focus-within 时出现；此前“用左上品牌图标原位替换 collapse icon”的方案已被用户否定。展开/折叠时一级图标位置仍必须稳定，折叠态仍需高质量 Tooltip。
- Generate 当前只显示 `Documents` 和 `Skills`，各自使用行尾 `+`；不显示顶层 `New`、通用 `+` 或重复动作。
- 切换 Document 不得重建整个列表、丢失滚动或明显闪动；Sources/Detail 等右侧 panel 默认应足够宽，并能占用全部剩余空间。
- 音频在第一次播放前也必须显示真实时长。
- 所有页面必须复用共享 Header、Button、Tooltip、Row、Form、Panel、Resizer、Dialog/Drawer 和状态模式；不能靠页面复制代码产生相近但不一致的 UI。
- 极简意味着删除噪音，而不是缩小字体。正常 running/connected/saved 保持不可见，文案使用最短动作，正式 UI 无需缩放即可舒适阅读。
- 必须实际打开 app.notion.com 和 chatgpt.com；全产品对照截图与可复用设计研究保存在项目中而不是 `/tmp`。每次大型 UI/UX 改动前后复用只读 `logue_product_designer` 审查真实 runtime。
- Storybook 根 URL 必须真实可用，并按 Foundations、Base Components、Feature Components、Page Compositions 组织。每个生产组件必须覆盖其所有有意义状态，Story 必须直接复用生产组件而不是复制 demo UI；Storybook 仍不能替代真实产品验收。
- Web、Storybook、README、Installer、默认 Skills、Prompt、Citation、系统 fallback、Demo 和测试/无障碍文案使用英文；用户自己的中文或多语言内容不得被误删或翻译。
- 永远使用 `main`；每个已验证批次使用小而原子的 commit，并立即 push `origin/main`。
- Mobile 当前不是优先项，不阻塞当前桌面 Web、Extension、Storybook、legacy 清理、Release 和设计终审；现有响应式不应故意退化，但暂不投入移动端专项优化。
- Linux 主机运行服务、MacBook Chrome/Web 通过局域网可变域名连接是最新 P0，不能与已后置的 Mobile 混为一项。Extension 必须可配置 Server URL、按具体 origin 请求权限、验证兼容 Logue 服务、在连接失败时允许 Retry/Change server，并在域名变化后无需重装即可恢复；所有 Extension API 都使用同一配置，不能有 localhost 旁路。
- Release 与一行安装必须支持 Linux 服务端资产、安装/覆盖、自动启动、可选 systemd 用户级开机启动和显式监听地址；隔离 Linux 验收机上的既有数据可视为不存在，但真实服务主机上的 Logue 数据仍必须保护。

## 用户对产品方向的连续纠正

- “生成内容”必须采用类似 Notion 的文档编辑 UX；整个产品也应采用 Notion 式简洁、内容优先的信息架构。
- Notion 是设计质量和心智模型参照，不是产品边界；Logue 必须保留 Notion 没有的跨网页输入、原始音频、来源链、项目记忆和 Agent 闭环。
- `View` 是技术名，不是合格的产品功能名；当前一级 UI 统一使用“生成”，可继续编辑的长内容对象使用“文档”。
- UI/UX 的具体形式不是用户预先规定的；用户只规定最终质量必须“非常好用”。产品设计必须自己判断，并用真实任务证据负责。
- 当前产品被用户明确判断为“远未完成、UI 很差、离目标太远”；任何旧的完成声明、截图结论或代理结论均失效，必须基于当前实现重新审查。
- 需要把全部截图交给 ChatGPT.com 做严格评审，并与 Notion、竞品进行比较；如果没有达到所有目标就继续做。

## 非用户要求

- “接受转写后必须再确认一次才能插入”不是用户要求。
- 任何模型生成的导航、确认次数、卡片、头像、统计、Agent Inbox 或 Context 页面都只是建议，必须经过价值与可用性判断。
- “必须先接受转写，然后再次确认插入/保存”是模型误读，必须删除；最新要求进一步删除前置审阅、重录、项目与 Tag 选择，只保留开始录音、停止并插入、取消。
- “写完规格、跑完测试、做完截图即可交付”不是用户要求，也不构成完成。

## 强制执行关系

- `/GOAL.md` 定义总目标、真实验收场景和完成判定；本文件定义用户事实。
- `docs/product-spec.md`、`docs/interaction-spec.md`、`docs/design-system.md` 只能细化二者，不能与二者冲突。
- 新用户要求或纠正出现时，先更新 `/GOAL.md` 与本文件，再修改实现。
